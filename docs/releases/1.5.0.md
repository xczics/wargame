## 本版改动

这一版是首次上线 Cloudflare 的成果：一条命令部署到 Cloudflare 免费计划，自带 R2 用量保护；服务端 CPU 大幅下降，页面同步进到免费计划的 10 ms 以内；外加几处修复。

### GM 与运维

- **一条命令部署到 Cloudflare**：`pnpm setup:cloudflare` 按提示完成登录、建库建桶、写配置、设置密钥、建表、部署、绑定 R2 公开域名和导入地图，可以反复运行。`docs/deployment.md` 第 5 节重写成完整的部署指南（准备、手动步骤、配置说明、免费额度、延迟、常见问题）。
- **线上配置单独成一个本地文件** `wrangler.production.jsonc`（数据库 id、域名、账号；不进 git、不进 Docker 镜像）：本地开发、测试和 Docker 照旧用自己的本地库；`pnpm run deploy`、`pnpm db:migrate` 用它。
- **R2 用量保护**：Worker 每 10 分钟查一次本月 R2 用量，存储、A 类、B 类任一项到免费额度的 50%（GM 规则可调）就暂停游戏（GM 后台和登录照常），并关掉 R2 公开域名，下个月自动恢复。GM 后台有用量报表和"解除用量暂停"命令。部署到 Cloudflare 时需要一个 API 令牌（`CF_API_TOKEN`）。Docker 和本地不受影响。
- **Worker 在数据库旁边运行**：部署脚本会把 Worker 固定在数据库所在的机房附近。一次同步要查十几次库，跨洲时以前要 3–4 秒，现在约 0.2–0.4 秒（另加玩家到服务器的一次往返）。
- **性能**（线上实测，状态同步的 CPU 中位数 29 ms → 6–12 ms）：
  - GM 规则按版本缓存，GM 没改规则时每个请求只读一行版本号；
  - 命令之后只重算真正受影响的视图（以前任何命令都会让整页重算）；
  - 产量、产量明细、上限、任职英雄的加成、科技定义等"常读少变"的数值存起来，变了才重算；建造命令少读 5 条；
  - 线上的后台任务改为每 10 分钟一次。
- R2 公开域名下，规则快照改用随机文件名，避免不透明科技的分组被人猜到文件名下载。

### 界面

- **拼图编辑器**：选了图片但没点"上传这一块"就保存时，会先自动上传；切换到另一张拼图时不会带上一张的图。
- **"GM 指定的英雄"奖励**：再次打开编辑器时，属性栏会显示之前填的值（以前是空的，要重新输入）。

### 修复

- 刷新页面后城池页空白，要点到别的页再回来才显示（1.4.1 引入）。
- 建筑刚完工、还没写入时，同一页的资源栏已经算上它的产量，产量表却还显示 0。
- 用量报表的说明在中文界面里是英文。

## 升级须知

- 新迁移 `0020`（用量保护）、`0021`（派生数值缓存）。部署在 Cloudflare 的照常先 `pnpm db:migrate` 再 `pnpm run deploy`；Docker 拉新镜像重建即可。
- **部署在 Cloudflare 的**：
  - 线上配置改到了本地文件 `wrangler.production.jsonc`。最省事的做法是运行一次 `pnpm setup:cloudflare`，按提示沿用你已有的数据库和桶，它会生成这个文件；也可以照 `docs/deployment.md` 5.3 手写。
  - `CF_API_TOKEN` 成为必需的密钥，没有它部署会失败（建法见 `docs/deployment.md` 5.5）。
  - 后台任务在线上改为每 10 分钟一次（`production` 环境的 `triggers`）。
- **1.4.1 设了 R2 公开域名的**：1.4.1 记录的规则快照仍是 `versions/1.4.1.json` 这个好猜的名字。升级结算还要用它，不要删；想藏起来可以把对象改成随机名，同时改 `engine_versions` 表里对应的 `file`。
