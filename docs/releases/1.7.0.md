## 本版改动

这一版有两个新玩法：英雄转世和商路开拓。

### 玩法

- **英雄转世**：90 级以上的英雄可以用转世丹转世，最多九转。
  - **转世时**：回到 1 级，经验清零；已分配的自由点并入天生属性，每转再给一笔自由点，天赋另加 2–6 点，补在最低的一维上。
  - **成功率**：第 N 转的成功率是 1/N，失败不会忘记已试过的次数，第 2N+1 次必成。
  - **境界**：没转过是凡人，一到九转依次是练气、筑基、金丹、元婴、化神、炼虚、合体、大乘、渡劫。英雄卡写境界和五星（一到八转每转半颗，九转是一整颗金星），转世丹的选人列表和结果邮件也写境界。
  - **转世丹从哪来**：聚宝阁卖 1,500 元宝；第 5 个秘境起有机会掉，越难的秘境、越靠后的任务越容易掉；商路第四章的商人每天卖一颗，1,200 元宝。
- **商路开拓**：新页签"商路"。默认三条商路：丝绸之路、茶马古道、海上航线，后一条的开局难度大约是前一条的中段。每条四章，每章一百多个地点，各章有自己的地形；地图一次只画一章，可以缩放、拖动（鼠标拖动、滚轮缩放；触控板双指滑动、捏合缩放；手机双指）。上一章的首领是下一章唯一的入口。
  - **剧情**：每个地点都有故事，分两段：打之前看到一段，打完补上后一段。每章几条支线在网状地图上展开、自由探索，最后在首领处收束；三条路连成一条主线，在海路终章汇合。
  - **从开拓据点出发**：外城建开拓据点后，在据点页组队：最多三名空闲英雄（任职的不能去），每人带一类兵（步、弓、骑三选一，各等级随意搭配），可以带辎重队和军医。出发时按预算的小时数一次付清部队维持，换成体力。
  - **走与停**：走路、打仗都花体力，走已经打通的路只要三分之一；点地图上已打通区域里的地点，开拓队按最短路一次走过去。体力用完或到时间回城；召回时按已花的体力折算回程，到时才回到城里，预算不退。
  - **每个地点都有敌军**：商人、休整地、奇闻都要先打下来，打下后才开店、讲后半段故事、补给。休整地第一次打下时查抄路霸的存货，以后每次路过再补一些。
  - **巢穴**：不在必经之路上的死胡同，每次出门都可以再清剿一次，经验和掉落照给。
  - **首次出现**：商路特有的道具和转世丹各有一个首次出现的地点，第一次打下必得一份；之后才会在别处掉落、商人才会卖。
  - **战斗**：各路兵团轮流互砍，回放里能看到像素小兵一刀一刀地打，可以跳过和重播。
    - 每一刀约有十分之一会落空，伤害有 ±15% 的浮动。
    - 兵种相克和攻城、野战用同一套规则：部队那部分攻击或防御 ×3，英雄和科技的相克加成照样生效。
    - 英雄的谋略越高，越会挑被自己克制的敌军下手；谋略低的会乱砍。组队时每名英雄写着"识破"率。
    - 伤亡和晋升与主战斗一样：低等级的兵先倒，按胜负分档；打赢后阵亡的额度让幸存者晋升。英雄固定承担四成伤害。
    - 军医每回合结束时按科技救回这回合倒下的一部分人，救回的也算晋升额度。
  - **敌将**：后面的敌军有将领带队，像不同阶段的玩家养出来的英雄：有名有姓，按酒馆招募的规则抽属性，自由点按常见的路数分配（先锋、统帅、猛将、谋将、军师）。越往后越强，开头的普通敌军群龙无首。敌军的兵种各章另有名字（马贼射手、雾海水兵……），数值不变。
  - **打赢之后**：地点就此打通，不再刷新；出战英雄得经验，偶尔顿悟，多得自由点；按章节掉落资源令状、加速、老兵召唤令、兵书、破境石、转世丹、套装，还可能掉落商单（永久开通）。
  - **商人**：每天四样货，用元宝买聚宝阁买不到的东西：老兵召唤令、24 小时加速、部分套装。
  - **难度**：每个成长阶段大致对应一章，章内由浅入深。普通敌营轻松，首领要全队上阵；海路终章要靠装备、科技或转世，满级不穿装备打不过。
- **开拓据点与互市**：外城可以建开拓据点（每城一座）。商路上的关键节点打通后会开通商单，每天能按资源价值用一种资源换另一种，有损耗。打通的地方越多损耗越低；据点等级越高，交易越快。
- **新道具**：
  - 六种老兵召唤令：在训练建筑里使用，直接得到 5、6 级老兵；
  - 三种 24 小时加速：只在商路商人处有卖；
  - 转世丹。
- **营寨守将、流寇头目**：和商路敌将一样，换成了像玩家养出来的真人（有属性、有加点路数），加成按玩家英雄的公式算；各级的强度按以前配好，大致不变，多了一点每路固定值。

### 界面

- **操作之后各页立即一致**：在一页做的事，别的页面马上显示出来，不用刷新（例如道具页用了秘境钥匙，秘境页随即解锁；聚宝阁买的道具，建筑页马上能用）。表单里随游玩变化的部分（有没有这件道具、谁空闲、驻军多少、资源够做几个）在浏览器里随数据即时更新；看过的表单再打开不再白屏等待。
- **加载画面**：打开网页时有真实的进度条（下载游戏程序、读取数据），更新后第一次打开时会提示要多等一会儿。
- **邮件按类型批量删除**：邮箱顶上选一类（秘境战报、出征战报、防守战报、补给短缺、转世结果、道具使用结果、系统邮件），一次删光；系统邮件只删已领取或没有附件的。
- **小助手**：科技页新开关"研究所空闲时自动科研"，按填平原则先升等级最低的科技，让研究所别闲着。
- **用户菜单**：顶栏只留"用户名 ▾"，点开是声望、GM 入口、语言、修改密码、退出，电脑和手机一样；语言选择从底栏挪了进来，名字只写语言本身（"中文""English"）。

### GM 与运维

- 新 GM 规则：
  - 转世 `rebirth.rules`；
  - 商路 `trade-routes.rules` / `capAttrs` / `aimAttrs` / `combat` / `epiphany` / `budgets` / `trade` / `merchant`；
  - 另加商路 `trade-routes.custom`：和内容同一格式的表，可以写敌将。
- GM 后台"操作"页可以给玩家重置密码：生成只显示一次的临时密码，原密码和已登录的设备立即失效，玩家登录后要先改密码；写审计日志。
- 人机验证被拒时，Worker 日志里会写 Cloudflare 给的原因（密钥不对、凭证过期等）。
- 新脚本 `scripts/reset-password.mjs <用户名>`：不进 GM 后台也能给玩家设临时密码，见部署文档"常见问题"。

### 修复

- 商路掉落的装备在结算里显示英文名。
- 道具使用表单在买到道具后要等下一次同步才出现。

## 升级须知

- 有四个新的数据库迁移：`0037_rebirth`（英雄转数）、`0038_trade_routes`（商路的进度、开拓队、交易、商人）、`0039_trade_routes_playtest`（召回、清剿记录、永久商单）、`0040_trade_routes_new_map`（换成新地图时清空商路进度和商单，从 1.6.4 直接升级时没有影响）。部署前先执行迁移（`pnpm db:migrate`）；Docker 镜像启动时会自动执行。
- GM 规则 `npc-camps.levels` 里守将的五个字段（人数、攻 / 防 / 血 / 伤亡 %）换成一个 `generals`（每名守将一个配方，如 `tavern/3/8`）；之前改过这几个字段的覆盖值需要按新写法重填。流寇的等级表同样换了列（内容表 `levels.csv`）。
- 新插件：`rebirth`、`trade-routes`、`npc-heroes`（NPC 英雄生成器）、`starter-trade-routes`（三条商路的内容）。
- 第三方插件：
  - 战斗服务新增：
    - `BattleSide.heroes`：直接指明领兵的英雄；
    - `BattleSide.generals`：没有英雄档案的 NPC 将领；
    - `laneNumbers` / `counterBoost` / `casualtyFactor` / `spreadDeaths` / `resultFactor`：一路兵的属性、相克倍数、伤亡系数、按人头分配阵亡、按胜负分档的系数，别的战斗也请用它们；
    - `finalLosses`；
    - `addGenerals`：给没有英雄的一方（NPC）补上将领；
    - `addRecovery` / `recovery`：多回合战斗里每回合救回的人。
  - 英雄服务新增 `reincarnate`、`freePerLevel`；装备内容服务新增 `roll`；NPC 英雄配方用 `npcHeroes.addRecipe`；邮件服务新增 `nameKind`（给自己的邮件类型起名，玩家可按类型批量删除）。
  - 前端：
    - 命令成功后由拥有数据的前端插件改浏览器里的数据：`game.afterCommand`、`game.patchView`；结果只有服务端知道的用 `game.markStale`。
    - 表单的前端部件（`forms.prepare`）可以在 `needs` 里声明数据视图、从 `data(视图)` 读，显示条件和会变的数字放在这里而不是服务端的 `prepare`。
    - 卡片新增 `UiCard.ref`（给前端插件用的 id，不显示）；奖励新增前端扩展点 `rewards.apply`。
    - 几个表单的数据形状改了（道具使用、训练、遣散、派兵、加点、转世丹等，见 `src/shared/api.ts`），自己写了这些表单部件的第三方插件需要跟着改。
