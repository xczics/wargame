## 本版改动

这一版主要是英雄与秘境的数值重做、像素风的装备界面，以及又一轮服务端减负：数据没变的后台同步，现在一次查询就能回答。

### 玩法

- **英雄**：
  - 冒险属性换算重做：防御主要看统率，攻击加上统率、武力的系数提高，生命跟着涨。中等武将的冒险攻防血约为以前的 1.6 倍。
  - 天赋整体 ×2：酒馆、书院 4–14，听曲楼 6–18。已有英雄的天赋也 ×2，并且补上已经升过的等级应得的属性点。
  - 女英雄（听曲楼）的天赋每项 1–3 点，分得更平均。
  - 饰品栏位与天赋脱钩，招募时单独抽定，1–10 栏都有可能；已有女英雄的栏位数不变。
- **秘境**：怪物整体变强，前期手感不变，后期更依赖装备颜色和招募地等级；爆率 ×1.5，很少空手而归。
- **装备**：
  - 盔、靴也有带兵 / 守城加成；装备的"每路生命"现在真正进入战斗，和将领的固定生命一样先于士兵承受伤害。
  - 十二种饰品各有侧重，冒险和带兵两边都有加成，单件约相当于一件常规装备。
- **军队**：
  - 步兵的特色资源由金属改为石头（训练和维持都是）；各兵种的金属用量降到 5%。
  - 维持费随等级增长得更慢（指数 0.8 → 0.6），高级兵更省：4 级兵每点属性的维持只有 1 级的约 31%。
  - 自己城池之间的行军快一倍，不受 3 分钟下限限制；单程不到 3 分钟的出兵时当场到达，界面上照样演出行军过程。
- **钱庄** 11–20 级每级产量 ×1.135（以前 ×1.12），10 级之后不再显得变缓。
- **小助手**：
  - 打营寨的系数按路算（每路 = 营寨一路守军 × 系数），兵够的前提下随机排兵种；低级兵不够时用同兵种的高级兵按攻击力顶上。
  - 可以跳过还在恢复期的营寨（默认开）。

### 界面

- **像素风装备界面**：英雄页中间是英雄的像素立绘（男女各一），穿上的装备直接画在身上，7 套常规装备、4 套饰品各有自己的样子，稀有度用颜色区分；悬停或点按格子看属性和操作。
- 装备的像素图标也用到了秘境商店、掉落清单、冒险战报、道具页和聚宝阁的宝箱。
- **战报**：
  - 只有发生战斗才发战报，派遣、运输、筑城不再发信。
  - 分路战况进攻方一律在左、防守方在右，写双方的名字（玩家写用户名，营寨、流寇写名字）。
- 切换页面时，60 秒内取过的数据直接显示，不再每次请求。
- 打开过的信件由浏览器缓存，再次打开不再请求。

### GM 与运维

- GM 发放"指定英雄"时可以指定六维天赋（每项 0–100）和饰品栏位数（0–10）。
- 奖池里的价值填 0 就是 0；不填才按权重计算。
- **服务端减负**：
  - 数据没变的后台同步只读一次数据库就回答（线上实测 2–6 ms）；
  - 同一请求里同时发出的查询合成一次数据库调用；
  - CSV 数据表在构建时解析好；
  - 命令开头一次读齐要用的数据：运输的数据库调用从 27 次降到 10 次，攻打从 16 次降到 4 次；
  - 到点的事件由浏览器发一次轻量的结算命令写库，之后的同步不再重复计算；
  - 每场战斗只存一份，进攻方和防守方的信件共用；
  - 各页面、表单只发数据，文字都在浏览器里拼。
- 新文档 `docs/workers-performance.md`：在 Cloudflare Workers 上开发的经验、踩过的坑和测量方法。

## 升级须知

- **新迁移** `0029`–`0032`（英雄扩展字段、天赋 ×2 与补点、时间线事件的玩家列、战斗表）。部署在 Cloudflare 的：先 `pnpm db:migrate`，再 `pnpm run deploy`，然后 `pnpm statics:refresh`。Docker：拉新镜像重建即可。
- **迁移 0030 会改动已有英雄**：天赋 ×2、补发已升等级的属性点、女英雄的饰品栏位写到她身上。升级前建议备份数据库。
- **玩家需要刷新页面**：前后端的数据格式变化较大。
- **第三方插件作者**：
  - 删掉了没人用的视图：`settlements.detail`、`settlements.map`、`shop.store`、`starter-heroes.roles`、`world-map.markers`、`terrain.window`、`items.inventory`、`heroes.candidates`、`battle.formation`、`equipment.bag`；`troops.units` 改成静态视图。
  - `settlements.addDetailExtender` 改名为 `settlements.addOutlineExtender`；`ReadApi.beforeUpgrade()` 改为返回 Promise。
  - 新增扩展点：`loot.definePool(pool, fill?)`（用到时才装）、`mail.onRemoved`、`ctx.views.wake`、命令的 `preload`、`timeline.addOwnerResolver` 的第三个参数（SQL 表达式）、前端的美术图标（`art:<方案>:<键>`，见 `docs/plugin-guide.md`）。
  - 表单的 `prepare` 应只返回数据，文字由前端插件在扩展点 `forms.prepare` 拼（见 `docs/development.md` 2.6.1）。
