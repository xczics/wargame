## 0. 总体

- **时代背景**：中国中世纪（宋、明一类），文案和美术风格向其靠拢。
- **美术**：暂时保持现在的简易图标 + 色块，之后再做美术资源。
  - **目标风格（未来）**：**45° 视角（等距 / isometric）、像素风**，**不支持旋转视角**。城池页要画出建筑本身（而不是现在的白块卡片），地图页的地形、城池也按同一视角绘制。具体见 `docs/design/ui.md` 第 5 节。
- 文案用中文，技术上通过 i18n 接口提供，将来可以加其他语言。

## 1. 资源

### 1.1 资源种类与生产建筑

共五种：

| 资源 | 生产建筑 | 说明             |
| ---- | -------- | ---------------- |
| 石头 | 采石场   |                  |
| 木头 | 伐木场   |                  |
| 粮食 | 农田     |                  |
| 金属 | 冶铁坊   | 新增             |
| 货币 | 钱庄     | 取代现在的"金币" |

（建筑名称已确认，可以随时再改。）

### 1.2 生产建筑数量限制

- **货币**：每个外城只能建一座货币生产建筑；资源要塞同样只能建一座。
- 其他四种资源的生产建筑可以建多座。

### 1.3 起步：资源建筑 1–3 级不耗自身资源

- 除了每座城池自带的基础产量（防卡死）外，**资源建筑在 1–3 级时，建造 / 升级不需要它自己产出的那种资源**，只需要其他资源。例如伐木场升到 3 级之前都不要木头，农田升到 3 级之前都不要粮食。
- 规则是通用的：凡是有产出的建筑，都不花自己产出的资源（没有写死具体建筑）；等级上限 3 做成可调规则 `buildings.ownResourceFreeUntil`（0 = 关闭）。被免掉的那部分直接省去，不转嫁到其他资源上。

### 1.4 扩展性

- 资源插件要能让其他插件**注册新种类的资源**。目前已经支持（`resources.define`），今后必须保持。

## 2. 部队

### 2.1 兵种与属性

三类战斗部队，每类 **6 个等级**：

| 兵种 | 特色   | 特色属性 |
| ---- | ------ | -------- |
| 步兵 | 均衡   | 生命     |
| 弓兵 | 防御多 | 防御     |
| 骑兵 | 进攻多 | 攻击     |

属性共三项：**攻击、防御、生命**（"生命"是新增的属性）。

### 2.2 属性成长规则

- **1 级**：三个兵种的基准属性相同，各自的特色属性 ×1.15，其余等于基准。
- **2 级**：各属性都是 1 级的 ×2，特色属性再 ×1.2（**乘算**，即特色属性合计为 1 级的 ×2.4）。
- **3–6 级**：每升一级，在前一级基础上（**复利**）：非特色属性 ×2.5（增加 150%），特色属性 ×3.5（增加 250%）。

### 2.3 数值表（暂定，之后再调）

以 1 级基准 = 10 计算。"特色属性"对步兵是生命、弓兵是防御、骑兵是攻击；"非特色属性"是其余两项。

**观察**（供之后调数值时参考）：

- 按这套规则，6 级兵的特色属性约为 1 级的 360 倍、非特色属性约 78 倍。
- 同一等级内，特色属性与非特色属性的差距逐级拉大：2 级是 1.38 倍，6 级是 5.3 倍。
- "量"按阶乘增长（1、2、6、24、120、720），比属性增长慢：6 级兵一个的"量"是 720，而它的特色属性是 1 级兵的约 360 倍。也就是说，用阵亡的低级兵"换"高级兵，从数值上看是划算的。

### 2.4 移动速度与行军

- 1 级：骑兵比步兵、弓兵快 15%。
- 步兵、弓兵：各等级速度不变。
- 骑兵：每升一级速度再 ×1.5（复利，见上表）。
- 出征军团的行军速度取**最慢单位**的速度。
- **行军距离**按直线距离（欧几里得距离）计算：√(dx² + dy²)，dx、dy 取绕地图接缝的最短方向（环面）。
- 行军时间**最短 3 分钟**，没有上限。
- **基础速度（暂定）**：步兵 / 弓兵 **120 格 / 小时**（可调规则 `starter-army.speed` 的 `base`）。10 格约 5 分钟，近处的目标基本按 3 分钟的最短时间到达。
  - 最初按"最慢的部队横跨一整张地图约 36 小时"定为 28.4 格 / 小时，试玩时用户反馈太慢（从首都到几格外的要塞要 20 多分钟），改为约 4 倍。
  - 地图是环形的，实际最远的两点相距 512 格（同一轴向）到约 724 格（对角），所以步兵实际最长行军约 4.3–6 小时。
  - 对应的骑兵速度：1 级 138、2 级 207、3 级 310.5、4 级 465.8、5 级 698.6、6 级 1,047.9 格 / 小时。

### 2.5 训练：兵营

- 三座不同的兵营：**步兵营、弓兵营、骑兵营**，分别训练步兵、弓兵、骑兵。
- 训练**花费资源和时间**。
- 训练出来的部队**不能再通过兵营升级**，只能在战斗中历练（见 2.6）。
- **2–4 级的直接训练预留道具接口**：
  - 如果道具插件没有为此设计专门的道具，则可以自由训练；
  - 如果设计了，则训练 2–4 级部队需要消耗道具提供的"训练额度"。

#### 2.5.1 兵营等级与可训练等级

兵营等级决定能直接训练出来的最高等级，最高 4 级；5–6 级只能通过战斗获得。

| 兵营等级 | 可训练的最高等级 |

| 1        | 1 级             |
| 5        | 2 级             |
| 10       | 3 级             |

- **10 级以后按乘法**：每升一级乘 0.95，即 11 级 52.2%、12 级 49.6%……

#### 2.5.3 训练花销与维持开销

**原则**：

- 训练：属性是两倍，花销要**比两倍多**；
- 维持：属性是两倍，开销要**比两倍少**。

**做法**：按一个兵的**总属性**（攻击 + 防御 + 生命）定总花销，再按比例分摊到五种资源。三个兵种同一等级的总属性相同（特色属性只是换了位置），所以总花销也相同，区别只在分摊比例。

- 总属性 S：1 级 31.5、2 级 67.6、3 级 196.6、4 级 588.1、5 级 1,808、6 级 5,704.6。
- 相对倍数 r = S ÷ 31.5（1 级为 1）。
- **训练总花销 = 100 × r^1.2**（指数大于 1，属性翻倍时花销约 ×2.3）。
- **每小时维持开销 = 1 × r^0.8**（指数小于 1，属性翻倍时开销约 ×1.74）。
- 基数 100、1 与指数 1.2、0.8 都做成可调规则。

**短缺的后果**：维持开销可以把余额压成负数（见资源规则），压到负数上限、资源耗尽时：

- **粮食或货币短缺 → 溃逃**：部队逃散（兵力直接减少）。
- **特殊资源短缺 → 降级**：步兵缺金属、弓兵缺木头时，部队降一级（例如 3 级步兵变成 2 级步兵）。**1 级兵无级可降，缺特殊资源时溃逃。**
- 骑兵的特殊维持资源就是粮食，所以骑兵只会溃逃，不会降级。

**逐步处理，而不是一次全部溃逃**。思路："如果资源情况不改善，则在 12 小时内溃逃（降级）到收支平衡"，每次只处理一点：

1. **缺口**：某资源耗尽时，缺口 = 该资源每小时的维持开销 − 每小时产出（都按当前规则、当前部队计算）。
2. **分轮处理**：资源耗尽时开始一段"短缺期"，每隔一段时间（暂定 **1 小时**）处理一轮，共 **12 轮**。
3. **每轮处理量**：本轮要削减的维持开销 = 当前缺口 ÷ 剩余轮数（第 1 轮 ÷12，第 2 轮 ÷11……最后一轮 ÷1）。按这个量换算成部队数，向上取整，至少 1 个兵。
   - 每轮都重新计算缺口，所以中途新训练了部队、产出变了，都会自动反映出来；如果资源情况不改善，第 12 轮结束时正好收支平衡。
4. **提前结束**：任一轮开始时，如果产出已经覆盖维持开销，或者余额已经回升到负数上限以上，短缺期结束，不再处理。之后再次耗尽则重新开始一段 12 轮的短缺期。
5. **处理顺序**：
   - **溃逃优先低级部队**：从 1 级开始往上。同一等级有多个兵种都消耗这种资源时，按各自数量比例分摊。
   - **降级优先高级部队**：从最高等级开始往下，每个兵只降一级。降级后该兵的维持开销下降（包括粮食、货币的那部分）。降到只剩 1 级兵时，1 级兵溃逃。
6. 轮间隔（1 小时）和总时长（12 小时）做成可调规则。

**在外行军的部队不参与溃逃 / 降级**，它们的维持开销在出征时一次付清：

- **出征时预付**：按本次出征往返的总时长（去程 + 回程）计算维持开销，出征那一刻从出发城池一次扣除。行军期间这些部队不再计入城池的持续维持开销。
- **资源不够则出征失败**：任何一种资源的余量不足以预付，出征就不能发出（这是主动花费，不能压成负数）。
- **中途召回按比例返还**：返还比例 = 没用上的时间 ÷ 预付的总时长。例如去程走了一半就召回，回程也只要一半的时间，实际用掉往返时长的一半，返还一半。
- 回城后，部队重新计入城池的持续维持开销。
- **阵亡不返还**：部队在战斗中阵亡，它预付但没用上的那部分不返还。设定上，出征的部队随身带着回程的干粮，仗没打赢就一起丢了。

### 2.6 战斗晋升

**基本规则**：N 级部队升到 N+1 级，需要在一场**非溃败**的战斗中，有"等量 N 个"同级战友阵亡。也就是说，每晋升 1 个 N 级兵，需要 N 份同级阵亡额度。

**"等量"的换算**：N 级部队的"量"是 N−1 级的 N 倍（见 2.3 表中"折合 1 级兵的量"）。

**结算**（每场战斗结束后，对每一方分别进行）：

1. 从 1 级开始，逐级往上计算，直到 6 级。
2. 每一级：本级额度 = 本场本级阵亡数 + 下一级（N−1 级）用剩并换算上来的额度。
3. 用本级额度晋升本级的幸存者，每晋升 1 个需要 N 份额度。**只有开战时就是 N 级的幸存者**才能晋升；本场刚从下一级升上来的，不再继续晋升。
4. 本级用剩的额度除以 (N+1)，加入 N+1 级的额度。
5. **优先同类型**：额度优先晋升同一兵种；同兵种晋升完后，剩余额度可以**跨兵种按 1:1** 使用（被晋升的同样必须是开战时就是该等级的幸存者）。
6. 结算完剩下的额度作废，**不保留到下一场**；6 级兵阵亡产生的额度同样作废。

**示例**：某兵种 1 级兵阵亡 100、幸存 20。

- 20 个幸存的 1 级兵全部升为 2 级，用掉 20 份 1 级额度；
- 剩下 80 份，除以 2，得 40 份 2 级额度，加入 2 级额度；
- 再用 2 级额度晋升开战时就是 2 级的幸存者（每个需要 2 份），剩余的除以 3 加入 3 级……依此类推。

**适用范围**：

- 进攻方、防守方都适用。
- 与 NPC 作战也适用，但 NPC 部队自己不晋升。

**溃败**：五路中只赢了 0–1 路的一方为溃败（见 3.6）。

- 溃败的一方不能晋升。
- 阵亡比例的思路：优势大 → 阵亡比例小；势均力敌 → 阵亡比例大；劣势大 → 溃败，阵亡比例反而减小（逃跑保住了一部分兵力）。具体由 3.8 的结果系数体现（大胜 ×0.3、险败 ×1.2、溃败 ×0.2）。

**跨兵种晋升**同样只能晋升"开战时就是该等级的幸存者"，与同兵种规则一致。

### 2.7 行军目的

（用户 2026-10-01 提出。）每次出兵都有一个**目的**，由目标格决定可选哪些（地图上选中格子后，只出现适用的表单）：

| 目的 | 目标                       | 到达后                                                                                                   |
| ---- | -------------------------- | -------------------------------------------------------------------------------------------------------- |
| 攻打 | 别人的城池、NPC 城池、空地 | 交战 / 掠夺（第 3 节），然后返回。**不能攻打自己的城池**。                                               |
| 派遣 | 自己的另一座城池           | 部队留在那里驻扎，行程结束；目标不能驻军（资源要塞）时，卸下辎重后返回。                                 |
| 筑城 | 空地                       | 在该格建立新城池（类型任选：分城、军事要塞、资源要塞），卸下辎重；部队留下驻守，资源要塞不能驻军则返回。 |

- **辎重**：派遣和筑城可以携带资源，总量不超过所带部队的**载重**（3.9 的载重）。出发时从出发城池扣除，到达后存入目标城池。攻打不能带辎重。
- **筑城材料**：建城费用（各类型的 `player-settlements.foundCosts`）在出发时扣除，随队携带，**不占载重**。筑城队出发前检查类型、数量上限、空地；到达时再检查一次，如果这时已不能建城（被别人占了、上限已满），筑城失败，材料和辎重全部带回。
- **维持开销**：仍按往返预付（2.5.3）。部队驻扎在目的地时，没用上的返程那一半随部队留在目的地（存入目的地的资源）。
- **召回**：去程中召回时，没用上的粮饷、辎重、筑城材料都随军带回。
- **英雄**：出兵时可以带英雄（上限见 5.4），只能选**挂靠在出发城池、处于空闲**的英雄；正在内政、驻守研究所或其他职务的英雄不能带兵。随派遣或筑城队留在新城池的带兵英雄，改为挂靠在新城池。
- **出兵表单**：辎重下方实时显示"已用 / 总载重"（总载重随所填的兵力变化），超出时不能提交；英雄栏位里，已在一个栏位选中的英雄不会出现在其他栏位，换出发城池时只列出挂靠在该城的空闲英雄。
- 首都仍在注册时自动建立；以前"在地图上直接建城"的做法改为只有 GM 可用（免费、立即）。
- 暂按：目的地驻军的维持开销从到达时刻开始计入目的地；派遣中的部队同样不参与溃逃 / 降级。

## 3. 战斗

### 3.1 阵列

- 战斗双方（进攻方、防守方）都分为 **5 路阵列**，**第 i 路对第 i 路**，五路各自交战。
- **每一路必须指定一个兵种**（步兵 / 弓兵 / 骑兵），**不能混排**；一路里可以包含该兵种的多个等级。
- 一路**可以不放部队**（0 人）：这一路的兵种照样指定，相克效果仍然生效，只是数值上不计入任何部队的属性。例如：
  - 进攻方某路 0 人 → 这一路攻击力为 0（×3 仍是 0）；
  - 防守方某路 0 人 → 这一路只有城墙的基础防御力（见 3.4）和其他固定加值（见 3.7），相克时同样 ×3。

### 3.2 进攻方：出征前布阵

- 出征时，玩家为 5 路各指定一个兵种，并分配部队（等级、数量，可以为 0）。
- **完全自由**：不要求三个兵种都出现，同一兵种可以占多路，带出的每个部队都由玩家明确放进某一路，不存在"没有位置的兵种"。
- 阵列在出发时确定，行军途中不能更改。
- **出征表单**：五路逐路排：每路选一个兵种，再按等级填数量（只列出发城池有的等级）；辅助兵种单独一栏（不进阵列）。每个数量框显示"最多 N"：出发城池该兵种（该等级）的数量减去其他各路已填的数量；超出的框标红。（用户 2026-10-01 要求。）

### 3.3 防守方：城墙布阵

- 防守阵列在**城墙**（见 3.4）上设置（城池页点开城墙），**随时可以更改**，以战斗发生时的设置为准。没有城墙的城池（城墙出现之前建的旧城池）按默认阵列防守，建好城墙后才能修改。
- **守城战所有驻军都参战**：阵列设置的是"每一路是哪个兵种"，而不是具体数量。
- **一个兵种对应多个阵列时自动均分**：例如骑兵被放在第 1、3 路，则所有骑兵（按等级分别）平均分到这两路；除不尽的余数按阵列顺序依次多分一个。
- **校验**：设置防守阵列时，**三个兵种必须各至少占一路**，否则拒绝。这样所有驻军都有位置。
- **兜底**：万一阵列里没有某个兵种（例如以后新增了兵种、旧数据），该兵种的驻军**不参战**，不报错。
- **默认阵列**：随机生成，**三个兵种都至少出现一次**。在**第一次被读取**时确定（玩家查看城墙、进攻结算等），之后保持不变，直到玩家自己修改。
  - 实现注意：只读视图里的写入会被丢弃，所以"随机"要用城池 id 做种子生成，保证落盘之前每次读到的都是同一个阵列；在第一次有写入的时机（例如战斗结算、玩家修改）保存下来。

### 3.4 城墙

- **所有玩家城池都有城墙**：首都、分城（内城）、军事要塞、资源要塞。**默认 1 级**（建城时自带，不用花费）。
- 只能建一座（`unique`）。
- **资源要塞**不能驻军，但城墙照样提供基础防御力，而且**比其他城池更高**（见下表）；它同样要设置防守阵列（五路全是 0 人，只靠城墙和相克）。

**造价**（1–7 级见下表；8 级以后与其他建筑相同：花销每级 ×1.3、时间每级 ×1.25，上限 20 级，可用道具突破）：

| 等级 | 石头         | 木头  | 金属 | 货币  | 时间         |
| ---- | ------------ | ----- | ---- | ----- | ------------ |
| 1    | （默认拥有） |       |      |       |              |
| 2    | 350          | 250   | 50   | 80    | 1 分 30 秒   |
| 3    | 600          | 420   | 100  | 140   | 4 分         |
| 4    | 1,000        | 700   | 180  | 240   | 10 分        |
| 5    | 1,700        | 1,200 | 300  | 400   | 25 分        |
| 6    | 2,900        | 2,000 | 500  | 700   | 1 小时       |
| 7    | 5,000        | 3,400 | 850  | 1,200 | 2 小时 20 分 |

思路：城墙以石头为主，木头其次，金属、货币少量；每级约 ×1.7，与兵营的曲线相近。

**效果**：

- **基础防御力**：每级提供一份，线性增加，**每一路都获得全额**。暂定**每级 100**（相当于 10 个 1 级兵的防御力）；**资源要塞每级 150**。两个数都做成可调规则。
- **防御加成**：每 5 级 +5%，**加法叠加**：5 级 5%、10 级 10%……25 级 25%；**25 级以上不再增加**，只继续增加基础防御力。
- 防守方某一路的防御力 =（该路部队防御之和 + 城墙基础防御 + 其他固定加值）×（1 + 城墙加成 + 其他百分比加成）× 相克倍数。城墙加成与科技、英雄等其他百分比加成按**加法叠加**（见 3.7）。

| 城墙等级         | 1   | 5   | 10    | 15    | 20    | 25    | 30    |
| ---------------- | --- | --- | ----- | ----- | ----- | ----- | ----- |
| 基础防御（每路） | 100 | 500 | 1,000 | 1,500 | 2,000 | 2,500 | 3,000 |
| 资源要塞（每路） | 150 | 750 | 1,500 | 2,250 | 3,000 | 3,750 | 4,500 |
| 防御加成         | 0%  | 5%  | 10%   | 15%   | 20%   | 25%   | 25%   |

- 城墙之外的基础防御将来由 **"防御设施"插件** 补充：在城墙上训练防御设施，提升基础防御数值（通过 3.7 的固定加值接入），具体规则在设计该插件时再定。

### 3.5 兵种相克

三个兵种循环相克：

| 克制方 | 被克制方 |
| ------ | -------- |
| 骑兵   | 步兵     |
| 步兵   | 弓兵     |
| 弓兵   | 骑兵     |

**相克加成**（在同一路交战的双方之间判断，同兵种不触发）：

- 进攻方的兵种克制防守方 → **进攻方攻击力 ×3**；
- 防守方的兵种克制进攻方 → **防守方防御力 ×3**。
- 倍数 3 做成可调规则（`ctx.config.define`），便于调平衡。
- 每路只有一个兵种，所以一路里最多只有一方触发加成。

**观察**：×3 的相克加成比升一级还大（3 级以后非特色属性每级 ×2.5）。防守方随时能改阵、进攻方出发后不能改，猜对相克的收益很高——这是有意的设计：**相克就是要碾压**。

**侦察**：不设专门的侦察手段。想摸清对方阵列，就派少量部队（哪怕一个兵）去打一次，看战报。**进攻方的战报一定能送回**，即使部队全部阵亡；战报按路显示双方的兵种、兵力和损失。

### 3.6 胜负：按胜出路数

每一路分出胜负后，按各方**赢下的路数**决定整场结果（双方赢的路数相加为 5）：

| 赢的路数 | 结果 | 对方结果  | 伤亡系数（3.8） |
| -------- | ---- | --------- | --------------- |
| 5        | 大胜 | 溃败      | ×0.3            |
| 4        | 胜   | 溃败      | ×0.65           |
| 3        | 险胜 | 险败      | ×1（基准）      |
| 2        | 险败 | 险胜      | ×1.2            |
| 0–1      | 溃败 | 胜 / 大胜 | ×0.2            |

- 大胜、险胜、险败、溃败四档及其系数由用户确定；4 路（"胜"）是插值补的中间档，系数取大胜与险胜的中点。
- 掠夺量同样按这几档设定，见 3.9。
- 溃败的一方不能晋升（2.6）；其余结果都可以晋升。
- **某一路打平算防守方赢**，所以双方赢的路数之和总是 5。

### 3.7 数值修改器（给其他插件预留）

战斗里用到的数值都要留出修改接口，让科技、英雄、道具等插件可以加成，不要在战斗代码里写死。每个数值支持两种修改：

- **固定加值**：直接加一定的基础数值（例如某英雄为每一路 +200 防御），与部队属性、城墙基础防御相加；
- **百分比加成**：与城墙的防御加成一样，**所有百分比加法叠加**后再乘（例如科技 +10%、英雄 +15%、城墙 +5% → ×1.30）。

预留的数值：

| 数值                 | 用于       | 例子                         |
| -------------------- | ---------- | ---------------------------- |
| 攻击力               | 双方每一路 | 科技"兵法"+5% / 级；英雄统率 |
| 防御力               | 双方每一路 | 科技"筑城"；守城英雄         |
| 生命                 | 双方每一路 | 科技、道具                   |
| 城墙基础防御（每级） | 防守方     | 科技；防御设施               |
| 相克倍数             | 双方       | 某些英雄让相克更强（预留）   |
| 伤亡系数             | 双方       | 某些英雄减少己方伤亡（预留） |

- 修改可以限定范围：只对某个兵种、某个等级、某一方（攻 / 守）、某类城池（例如只对资源要塞）生效。
- 每一路的最终数值 =（部队属性之和 + 城墙基础 + 固定加值）×（1 + 百分比加成之和）× 相克倍数。
- 实现上做成 stat（`stats.define` / `stats.contribute`），现有的 `troops.addPowerModifier`、`armies.addAttackModifier` 要扩展成这种"固定 + 百分比"的形式；战报里列出每项加成的来源（沿用现在的 `attackFactors`）。
- 进攻方的加成来自进攻方（科技、随军英雄等），防守方的加成来自被攻击的城池及其主人。

### 3.8 战斗公式

每一路单独计算。下面的"攻击力 / 防御力 / 生命"都是这一路里该方的**合计**：部队属性之和，加上城墙基础防御（仅守方防御）和固定加值，乘百分比加成，再乘相克倍数（3.4、3.5、3.7）。

**1. 定胜负**：比较**进攻方攻击力**与**防守方防御力**。

- 攻击力 > 防御力 → 进攻方赢这一路；
- 否则（包括相等）→ 防守方赢这一路。

**2. 伤害**：双方都用"对方攻击力 − 我方防御力"：

- 守方受到的伤害 = 攻方攻击力 − 守方防御力
- 攻方受到的伤害 = 守方攻击力 − 攻方防御力
- 小于 0 按 0 算（对方攻击打不穿我方防御，没有伤亡）。
- **先截断**：伤害最多等于我方这一路的生命合计（即伤亡比率最多 100%），超出部分作废，之后才乘结果系数（第 4 步）。
- 这一路我方没有部队（生命为 0）时，没有伤亡。
- 相克加成按 3.5 只作用于"攻方攻击力、守方防御力"，守方攻击力、攻方防御力不受相克影响（已确认）。

**3. 分摊到各等级**：

1. 伤害**按人数比例**分给这一路里的各个等级（每个兵分到的伤害相同）。由于低级兵单个生命少，同样的伤害会让低级兵死得多、高级兵死得少。
2. **从 1 级往上逐级**计算阵亡人数：本级阵亡 = 本级分到的伤害 ÷ 单个兵的生命，最多为本级全部人数（先按小数计，不取整）。
3. 低级兵"不够死"时（分到的伤害超过本级全部生命），**剩余的伤害按人数比例分给所有更高等级**，再继续往上算。
4. 因为第 2 步已经截断，伤害总能被这一路的部队吸收完。

**4. 汇总并乘结果系数**：

- 把各路的阵亡人数按**兵种 + 等级**加起来（同一兵种可能分布在多路），再按整场结果（3.6）乘伤亡系数：大胜 ×0.3、胜 ×0.65、险胜 ×1、险败 ×1.2、溃败 ×0.2。
- 系数做成可调规则，也接受修改器（3.7）。

**5. 取整**：四舍五入得到每个兵种、每个等级的阵亡人数，且**不超过该级实际人数**（险败 ×1.2 可能让结果超过人数）。阵亡人数用于晋升结算（2.6）。

**示例**（城墙 1 级、无其他加成）：

| 情形                               | 攻方攻击 / 防御 / 生命 | 守方攻击 / 防御 / 生命 | 这一路 | 攻方伤亡比率 | 守方伤亡比率            |
| ---------------------------------- | ---------------------- | ---------------------- | ------ | ------------ | ----------------------- |
| 100 个 1 级骑兵 对 100 个 1 级骑兵 | 1,150 / 1,000 / 1,000  | 1,150 / 1,100 / 1,000  | 攻方胜 | 15%          | 5%                      |
| 150 个 1 级骑兵 对 100 个 1 级骑兵 | 1,725 / 1,500 / 1,500  | 1,150 / 1,100 / 1,000  | 攻方胜 | 0%           | 62.5%                   |
| 100 个 1 级骑兵 对 100 个 1 级步兵 | 3,450 / 1,000 / 1,000  | 1,000 / 1,100 / 1,150  | 攻方胜 | 0%           | 100%（原为 204%，截断） |

（伤亡比率 = 伤害 ÷ 生命，截断后；第三行骑兵克步兵，攻方攻击 ×3。）若整场是攻方险胜，第一行最终攻方伤亡 15% × 1 = 15%、守方 5% × 1.2 = 6%。

**多等级分摊示例**：守方一路有 100 个 1 级步兵（生命各 11.5）和 10 个 3 级步兵（生命各 96.6），受到 1,500 伤害。

- 按人数分：110 人，1 级分到 1,500 × 100/110 ≈ 1,363.6，3 级分到 ≈ 136.4。
- 1 级全部生命只有 1,150，100 人全部阵亡，剩余 213.6 分给更高等级（只有 3 级）。
- 3 级共受 350 伤害，阵亡 350 ÷ 96.6 ≈ 3.62 人。
- 险胜（×1）：阵亡 1 级 100 人、3 级 4 人；险败（×1.2）：1 级 120 → 不超过人数取 100 人，3 级 4.35 → 4 人。

**观察**（供调数值参考）：

- 兵力相当时双方伤亡都很小（第一行只有 5%–15%），伤亡主要来自兵力差距和相克。这与 2.6 "势均力敌 → 阵亡比例大"的思路不完全一致，目前靠险胜 ×1 / 险败 ×1.2 的系数弥补。
- 赢下一路的一方不一定伤亡更少（第一行攻方赢了这一路，却死得更多），因为定胜负只看"攻方攻击 vs 守方防御"，伤亡还取决于守方攻击。
- 相克 ×3 等于碾压（有意为之）：同等兵力下被克的一路会被打满（截断到 100%）。
- 按人数分摊伤害时，混编的低级兵实际上在给高级兵"挡刀"：1 级兵单个生命 10 左右，6 级兵上千，同一路里低级兵会先死光。这是有意的设计：**出征要"配炮灰"**，用低级兵保护高级兵。

### 3.9 掠夺

- 进攻方**赢下 3 路以上**（险胜、胜、大胜）才能掠夺；险败、溃败不掠夺。防守方不掠夺。
- 掠夺量按守方城池**每种资源库存的百分比**计算：

| 进攻方结果 | 赢的路数 | 掠夺比例        |
| ---------- | -------- | --------------- |
| 大胜       | 5        | 50%             |
| 胜         | 4        | 35%（线性插值） |
| 险胜       | 3        | 20%             |
| 险败、溃败 | 0–2      | 0               |

- 比例做成可调规则，也接受修改器（3.7）。

**计算顺序**（每种资源分别算）：

1. **按比例结算**：应掠夺量 = 守方该资源库存 × 掠夺比例（库存先结算到战斗时刻）。
2. **隐藏仓库截断**（先隐藏仓库、后载重，顺序已确认）：守方至少保留隐藏仓库的容量（见下），即掠夺量不超过"库存 − 隐藏容量"，不足时为 0。
3. **载重截断**：各资源掠夺量之和不超过进攻方**幸存部队**的总载重；超出时各资源按比例同样缩减。超出载重的部分**掠夺失败**，留在守方。

**载重**（每个兵能带回的资源总量，不分资源种类）：

- 载重 = 基数 20 × 等级 × 兵种系数，**按等级线性增长**。基数、兵种系数做成可调规则；总载重做成 stat，接受修改器（3.7），例如科技、辎重队（3.10）。
- 兵种系数：步兵 1、弓兵 1、骑兵 1.25（马匹驮运，多带一点）。
- 只有**战斗后幸存**的部队计入载重，阵亡的不算。

| 等级 | 步兵 / 弓兵 | 骑兵 |
| ---- | ----------- | ---- |
| 1    | 20          | 25   |
| 2    | 40          | 50   |
| 3    | 60          | 75   |
| 4    | 80          | 100  |
| 5    | 100         | 125  |
| 6    | 120         | 150  |

**隐藏仓库**（新建筑）：

- 每级为**每种资源**各保护 **500**，线性增加，做成可调规则；保护量做成 stat，接受修改器（3.7）。
- 所有玩家城池都可以建（包括资源要塞），每座城池一座（`unique`）。
- 现在普通仓库带的"防掠夺"效果移到隐藏仓库，普通仓库只提供库存上限。
- 造价（1–7 级见下表；8 级以后与其他建筑相同）：

| 等级 | 石头  | 木头  | 货币 | 时间       |
| ---- | ----- | ----- | ---- | ---------- |
| 1    | 120   | 100   | 20   | 30 秒      |
| 2    | 200   | 170   | 35   | 1 分 15 秒 |
| 3    | 350   | 290   | 60   | 3 分       |
| 4    | 600   | 500   | 100  | 8 分       |
| 5    | 1,000 | 850   | 170  | 20 分      |
| 6    | 1,700 | 1,450 | 290  | 50 分      |
| 7    | 2,900 | 2,450 | 500  | 2 小时     |

**示例**：守方有粮食 10,000、木头 2,000，隐藏仓库 2 级（每种保护 1,000），进攻方大胜（50%），幸存 120 个 1 级骑兵（载重 3,000）。

- 按比例：粮食 5,000、木头 1,000；
- 隐藏仓库截断：粮食上限 9,000，仍为 5,000；木头上限 1,000，仍为 1,000；
- 载重截断：合计 6,000 > 3,000，按比例缩为粮食 2,500、木头 500。

### 3.10 辅助兵种（预留插件接口）

将来可能由"辅助兵种"插件加入不参加阵列的特殊部队，例如"军医""辎重队"。战斗插件要为此预留接口，而不是把这些规则写死在战斗代码里：

- **注册不参战的兵种**：兵种注册接口要允许声明"辅助"兵种。辅助兵种可以随军出征或驻守，但**不放进五路阵列**，不计入攻击、防御、生命。它们的训练、维持、行军速度照常由兵种系统处理。
- **伤亡修改钩子**：在 3.8 的**每一个环节**都可以修改数值——伤害（第 2 步）、按等级分摊（第 3 步）、汇总与结果系数（第 4 步）、最终阵亡人数（第 5 步）。例如"军医"按随军数量降低最终阵亡。每次修改都写进战报，注明来源。
- **载重**：辅助兵种注册时同样可以有载重；也可以通过总载重的 stat（3.9）加成。例如"辎重队"不参战，获胜时提供额外载重帮忙运货。
- **辅助兵种参与伤亡**：辅助兵种自己也可能伤亡，例如辎重队在失败时帮忙"挡刀"（分担一部分阵亡），通过伤亡修改钩子实现。
- 军医、辎重队的具体数值和规则，在设计辅助兵种插件时再定。

### 3.11 NPC 阵列

- NPC 的阵列**随机指定**：每场战斗开始时，为 5 路随机指定兵种，并把 NPC 的部队按兵种均分进去。
- 实现注意：随机结果要由战斗本身决定（例如用时间线事件 id 做种子），保证命令重试时结果一致（见 AGENTS.md "命令可能被重试"）。
- NPC 没有城墙，不享受城墙的基础防御力和加成。

## 4. 地图

### 4.1 概况

- 地图 1024 × 1024 格，两个方向首尾相接（环面，沿用现有实现）。
- 每一格有一种**地形**。地形影响建在这一格上的城区的资源产出。
- 地图在开服时一次生成（导入 CSV 或随机生成），之后**固定不变**：玩家不能改造地形（开垦、修路等），只有 GM 能调整（4.5）。

### 4.2 地形种类

| 地形 | 说明                           | 目标占比 |
| ---- | ------------------------------ | -------- |
| 草地 | 最常见的平地，适合耕种         | 33%      |
| 森林 | 成片分布                       | 20%      |
| 丘陵 | 山地周围的过渡带               | 12%      |
| 山地 | 连绵的山脉                     | 8%       |
| 荒漠 | 干旱地区，产出差，但有商路之利 | 12%      |
| 池塘 | 湖泊、池塘，大小有上限         | 5%       |
| 河流 | 从高处流向湖泊的水系           | 5%       |
| 道路 | 连接各处的官道                 | 4%       |
| 矿脉 | 稀有，零星分布在丘陵和山地里   | 1%       |

- **任何地形都可以建城**，地形不限制建城、不限制城区类型。
- 地图上用不同颜色显示地形（颜色使用设计 token，浅色、深色各一套），图标以后随美术资源一起做。
- **全图地形默认对所有人可见**。预留"迷雾"插槽：以后的迷雾插件可以决定某个玩家能看到哪些格子，地图视图按它过滤；没有迷雾插件时全部可见。
- 地形种类可以由其他插件注册（与 `resources.define` 类似），上表是默认内容。

### 4.3 地形对产出的加成

地形加成只作用于**外城**和**资源要塞**（有资源建筑的城区），**只按该城区所在的那一格**计算，相邻格子不算；首都、分城的内城与军事要塞没有资源建筑，不受影响。

| 地形 | 粮食 | 木头 | 石头 | 金属 | 货币 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| 草地 | +20% |      |      |      |      |
| 森林 | −10% | +30% |      |      |      |
| 丘陵 |      |      | +20% | +15% |      |
| 山地 | −30% | −10% | +35% | +30% |      |
| 荒漠 | −40% | −40% | +10% | +10% | +15% |
| 池塘 | +25% |      |      |      | +5%  |
| 河流 | +15% |      |      |      | +15% |
| 道路 |      |      |      |      | +25% |
| 矿脉 | −20% |      | +20% | +60% |      |

- 思路：每种地形有明确的"特长"，也有代价；货币只能靠水路、道路、商路（荒漠）加成，与"每个外城只能建一座钱庄"相配合，让选址有取舍。
- 先按这版上线；数值不合理时，先由 GM 在线调整测试，确定后再写回 CSV 文件。
- 地形加成与科技等其他百分比加成**加法叠加**：产出系数 = 1 + 地形加成 + 其他加成，最低为 0。
- 数值表放在插件自带的 CSV 里，GM 可以实时修改（部分覆盖），遵循"GM → CSV → 默认值"的覆盖顺序。
- 改变加成（GM 改表、改地形）前要先结算受影响城池的资源（与其他改变产率的规则一致）。
- 地形**不影响行军速度**。
- 预留接口：其他插件可以按地形提供别的效果（例如守城防御），通过查询"某格是什么地形"实现；本版只做产出加成。

**对玩法的影响**：

- 外城必须与已有城区相邻，所以首都周围的地形决定了一座城的发展方向；建外城的候选格要显示地形和加成。
- 地图系统不对选址设限制（例如新账号首都的位置），也不负责 NPC 城池的分布；这些由城池系统和 NPC 插件自己决定。

### 4.4 开服：导入或随机生成

两种方式都是**运维脚本**，在开服前执行一次（`pnpm map:generate`、`pnpm map:import`），不是游戏内命令。生成的地图先存成 CSV 文件，可以检查、手工修改、存档，再导入；所以"随机生成"其实是"预烘焙"：生成 → 检查 → 导入。

**CSV 格式**：1024 行 × 1024 列，每个单元格是地形 id（如 `grass`、`forest`）；第 1 行对应 y = −511，第 1 列对应 x = −511。可以用表格软件或脚本编辑。

**导入**：

- 校验尺寸和地形 id，不合法就整份拒绝。
- 新服、已有玩家的服务器都可以导入。已有城池的产出按新地形**立即变化**：导入时先结算所有受影响城池的资源，再切换地形。
- 导入会整张覆盖现有地形，执行前要求确认。
- 没有导入过地图时，所有格子按默认地形（草地）处理，游戏照常运行。
- 本地导入必须带 `--local --persist-to .data/local`（与其他本地数据命令一致）。

**随机生成**（同一个种子和参数一定生成同一张图）：

1. **无缝噪声**：地图是环面，用四维噪声（把 x、y 各映射成一个圆）采样 OpenSimplex 噪声，保证地图边缘无缝衔接。
2. **高度**：多层分形噪声（fBm）+ 域扭曲（domain warping），让地貌自然；叠加脊状噪声（ridged noise）生成**连绵的山脉**，而不是零散的山头。
3. **水系**：
   - 用 Priority-Flood 算法填平洼地，填得较深的洼地成为**湖泊 / 池塘**（单个水体面积有上限，避免出现大海）；
   - 按坡度计算水流方向和汇水量，汇水量超过阈值的格子成为**河流**，河流从高处流向湖泊。
4. **湿度**：独立的噪声，再按离水体的距离加湿，河湖附近更湿润。
5. **地形分类**：按高度、湿度的**分位数**划分（高 → 山地 → 丘陵；低湿度 → 荒漠；高湿度 → 森林；其余草地），用分位数而不是固定阈值，保证每张图的占比都接近 4.2 的目标。
6. **矿脉**：在丘陵、山地里用高频噪声挑出零星的小片。
7. **道路**：用泊松圆盘采样在草地、河边选出若干"集镇"点，做 Delaunay 三角剖分，保留最小生成树再加少量额外的边（让路网有环路），每条边用 A\* 按地形代价寻路（山地、水面代价高，已有道路代价低，道路会自然合并）。
8. **清理**：用连通域检查去掉过小的零碎地块（并入周围最多的地形），矿脉和池塘除外。
9. **公平性检查**：把地图分成 64 × 64 的区块，统计每块的"产出价值"（按 4.3 的加成折算），偏离全图平均太多的区块做局部调整，仍不达标就换种子重来。

**输出**：CSV 地图、一张预览图（PNG）、一份统计（各地形占比、区块公平性），供运营检查后再导入。所有参数（目标占比、山脉数量、水体上限、路网密度等）都可以在生成时指定。

### 4.5 GM 操作

- GM 可以修改单个或一片格子的地形（`privileged` 命令，写审计日志）；受影响的城池先结算资源，再按新地形生效。
- GM 报表：全图各地形占比、各地形上的城区数量。

### 4.6 地图总览

- 地图页右侧的"周边 NPC 城池"：以**当前地图中心**为圆心，列出一定格数内（10 / 20 / 30 / 50 格可选，最大半径由 GM 规则 `settlements.nearbyRadius` 决定，默认 50）的 NPC 城池，按直线距离从近到远排列，显示类型、坐标、距离；移动地图时列表跟着变；点击一项，地图移到那一格并选中它（下方出现出兵表单）。（用户 2026-10-01 提出；最初暂按"以选中的城池为圆心"实现，用户要求改为地图中心。）

### 4.7 实现注意

- 100 万格不适合一格一行存储。按区块存：例如 32 × 32 为一块，每块一行，内容是 1,024 个地形编码拼成的字符串，全图约 1,024 行、1 MB 左右；查看地图窗口时只读涉及的几块。实现前查阅 D1 的限制确认。
- 地形数据归地形插件所有（表名以插件 id 为前缀），地图显示、产出加成等都通过服务读取。
- 在已有玩家的服务器上导入时要先结算资源，这需要游戏引擎参与，所以导入不能只是直接写数据库的脚本：脚本负责校验和上传，由 Worker 端的 GM 接口分批写入并结算。
- 现在的 `resources.productionFactor` 是整座城池、所有资源共用的一个系数；地形加成需要**按城区、按资源**区分，要扩展这个接口。

## 5. 英雄

### 5.1 招募

- 英雄在三座建筑里招募：**酒馆**、**书院**、**听曲楼**。
- **招募地点只影响英雄的属性**（5.3）；招募完成后，所有英雄统一管理，不再区分出身。
- 三座建筑都是内城建筑（首都、分城），每座城池各限一座。
- **招募方式**：每座建筑定时刷新若干名候选英雄，玩家花货币从中挑选招募；建筑等级越高，候选越多、刷新越快。
- **英雄数量上限**：做成 stat（`stats.define`），由建筑、科技等提高。

### 5.2 六维属性

| 属性 | 含义     | 作用                                    |
| ---- | -------- | --------------------------------------- |
| 武力 | 个人勇武 | 带兵时，部队**攻击力** +%               |
| 统率 | 指挥调度 | 带兵时，部队**防御力**、**生命** +%     |
| 智谋 | 用兵计策 | 带兵时，**伤亡系数** −%（减少己方阵亡） |
| 政务 | 治理地方 | 内政时，**资源产出** +%、建造时间 −%    |
| 学识 | 学问见识 | 驻守研究所时，**科研**时间 −%           |
| 魅力 | 声望人望 | 内政时，**训练**时间 −%、部队维持 −%    |

- 前三项偏"武"，后三项偏"文"：武将适合带兵，谋士适合内政、研究。各属性何时生效见 5.4。
- 数值刻度：普通英雄每项 1–100；听曲楼英雄可以**超过 100**（"爆表"）。
- 作用的换算暂定为**每点 0.2%**（100 点 = +20%，150 点 = +30%），换算系数做成可调规则。所有效果都通过战斗（3.7）和资源、建筑、科技、兵营已有的百分比加成接入，与其他加成**加法叠加**。

### 5.3 招募地点与属性

| 招募地点 | 类型 | 武力   | 统率   | 智谋   | 政务   | 学识   | 魅力   | 六维合计（约） |
| -------- | ---- | ------ | ------ | ------ | ------ | ------ | ------ | -------------- |
| 酒馆     | 武将 | 60–95  | 55–90  | 20–60  | 20–60  | 15–50  | 30–70  | 310            |
| 书院     | 谋士 | 15–50  | 30–70  | 60–95  | 55–90  | 60–95  | 30–70  | 360            |
| 听曲楼   | 稀有 | 60–110 | 60–110 | 60–110 | 60–110 | 60–110 | 90–150 | 540            |

- 每项在范围内随机；酒馆英雄的"武"三项、书院英雄的"文"三项必有一项接近上限，保证每个英雄都有突出的长处。
- 书院英雄的合计略高于酒馆，因为文职属性的作用（产出、科研）没有战斗属性那么直接。
- **听曲楼**：
  - 只招募**女性英雄**，**稀有**：候选出现的概率低（建议每次刷新 10% 的概率出现一名），招募花费高。
  - 数值**爆表**：六维全面偏高，魅力最高可达 150，另外随机一项"绝技"属性可以突破 100。
- 酒馆、书院只招募男性英雄。
- 英雄的名字从姓氏、名字字库随机组合（中国中世纪风格），走 i18n 接口；头像以后随美术资源一起做。
- 范围、概率、换算系数都放在插件自带的 CSV 里，GM 可调。

### 5.4 英雄的职务

每名英雄**同一时间只担任一种职务**，只有当前职务对应的属性生效（守城武将是例外，见下）：

| 职务       | 生效的属性       | 说明                                             |
| ---------- | ---------------- | ------------------------------------------------ |
| 空闲       | 无               | 招募后的默认状态                                 |
| 带兵       | 武力、统率、智谋 | 随军出征，作为这支军队的主将；军队回城前不能改派 |
| 内政       | 政务、魅力       | 坐镇某座城池，加成只作用于这座城池               |
| 驻守研究所 | 学识             | 驻守某座城池的研究所，加快该研究所的科研         |
| 插件职务   | 由插件决定       | 例如秘境冒险，见下                               |

- **英雄只能在挂靠的城池任职**：内政、驻守研究所的目标必须是英雄挂靠的城池。其他插件注册的职务可以声明例外（例如带兵的目标是军队）。改挂靠时，如果当前职务在原城池，英雄先卸任（回到空闲）再挂靠过去。（用户 2026-10-01 要求。）
- 内政、驻守研究所可以随时改派，加成立即变化（改变产率前先结算，与其他规则一致）。
- **同一职务可以有多名英雄**，人数上限做成 stat，GM 可调，科技等也可以提高：

| 上限                       | 默认 |
| -------------------------- | ---- |
| 每座城池的内政英雄         | 3    |
| 每个研究所的驻守英雄       | 2    |
| 每支军队的带兵英雄         | 3    |
| 每座城池的守城武将（见下） | 3    |

- 多名英雄的加成**加法叠加**：例如两名带兵英雄武力 80、60，部队攻击力 +16% +12% = +28%。

**挂靠与守城**：

- 每名英雄**挂靠**在玩家的某一座城池下（招募时挂靠在招募所在的城池，之后可以改挂靠）。
- **守城顺序**：玩家为每座城池排一个守城武将的**顺序表**（从挂靠在该城的英雄里选，可以多于 N 名，作为替补）。玩家没有指定时，按挂靠在该城的全部英雄的**武力 + 统率 + 智谋**从高到低自动排序。
- **结算时按顺序依次尝试**：城池被攻击时，从顺序表第一名开始，跳过**不在城里**的英雄，取前 N 名在城的英雄作为本场的守城武将。他们的武力、统率、智谋对守方全部五路生效。
- **在城**：空闲、内政、驻守研究所的英雄在城；带兵出征的不在城。插件注册职务时要声明担任该职务的英雄是否在城（例如秘境冒险不在城）。
- 守城武将不是职务，不打断其他任务：英雄做内政、驻守研究所的同时，也可以守城。

## 7. 城池与建筑

（最早的一批需求，来自用户，已实现；这里保留原意，作为玩法的依据。）

### 7.1 城池

- 类型：首都（主城）、城池（分城）、要塞。要塞分**资源要塞**（只能建仓库和资源建筑，不能驻军）和**军事要塞**（只能建仓库，可驻军）。
- 首都和分城 = 1 个内城 + N 个外城（N ≥ 1，玩家可动态扩建；上限由科技决定，道具可无视科技新建到另一个更高上限）。
- 外城：只能建资源建筑；栏位**数量随机**，可用道具提升。内城：只能建非资源建筑；栏位固定。内外城**共享同一个资源池和库存上限**。
- 有些建筑只能建在首都，有些只能建在分城。
- 地图网格：要塞占 1 格；首都 / 分城占格数随外城数量增加，默认上限 9 格（不用道具）。
- NPC 城池：要塞（抢兵）、据点（抢粮）等，由独立的插件实现，城池系统只留接口。
- 地图"伪球形"：x、y ∈ [-511, 512]，两个方向都首尾相接（实际是环面）。
- 首都在注册时自动建立；其他城池通过"筑城"行军建立（2.7）。

用户已拍板的决定：

| 问题     | 决定                                                                                                                            |
| -------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 外城布局 | 内城居中，外城逐个占相邻格；第 1–8 座在第一圈（满 3×3），更多（道具）在第二圈（最多 5×5 = 24 座外城）；新外城必须与已有城区相邻 |
| 外城栏位 | **数量**随机（默认 3–6，GM 可调），不区分栏位类型                                                                               |
| 建筑     | 有等级，建造 / 升级**耗时**，有建造队列                                                                                         |
| 首都     | 注册时系统随机分配空地（要求 3×3 全空）                                                                                         |

### 7.2 建筑

- 升级前先询问科技等插件是否拦截。
- 0–20 级之间有若干关键节点受科技控制；科技点满后最高 20 级（常规上限，GM 可按建筑调）；用道具**随机突破**，每个建筑实例的上限单独记录，最终无上限。
- 前 7 级的消耗 / 时间由策划表逐级给出；第 8 级起按第 7 级乘递增系数（每级花销 ×1.3、时间 ×1.25，可调）。
- 其他插件能新增建筑类型（例如"挑战系统"需要先在首都建"擂台"）。
- 建造可以取消，返还一半费用（可调）。

### 7.3 资源的余额与维持

- 驻军消耗资源维持。资源可以为**少量负值**（欠债下限，可调），压到下限时触发短缺后果（2.5.3 的溃逃 / 降级）。
- 产出不只做加法，支持百分比加成（科技、地形、英雄……）：`净产率 = 产出 × (1 + 各项加成) − 维持消耗`。
- 离线期间按需结算，最多结算 12 小时（可调）。

| 来袭敌军的情报等级                 | 斥候       | `armies.incoming` 按 stat 返回不同详细程度    |
| 进攻方削减守方城墙加成             | 神机营     | `battle` 修改器支持"对方的某项加成 −x"        |
| 晋升额度修正                       | 王师       | `battle.promotions` 接受修正系数              |

### 8.7 实现顺序建议

1. 数据与界面：CSV 加列、科技页按门类 / 阶显示树和连线、题注。
2. 只用现有接口的科技（建筑等级段、产出、库存、上限、战斗修改器、时间与维持修正）——约 30 项。
3. 逐项补 8.6 的新接口，接上剩下的科技。

## 9. 与现有实现的差异（供开发排期参考）

以下是本设计与当时代码的主要差别及实现情况（实现记录见 `docs/changelogs/`）：

- **资源**：从"粮食、木材、石料、金币"改为"石头、木头、粮食、金属、货币"；新增金属和冶铁坊，金币改名为货币、金矿改为钱庄。 ✅ 已实现。
- **货币建筑的数量限制**：现在只有"每座城池最多一座"（`unique`），需要新增"每个城区最多一座"的限制（外城、资源要塞各一座）。 ✅ 已实现。
- **兵种**：从"民兵、枪兵"改为步 / 弓 / 骑三类 × 6 级；新增"生命"属性；属性、速度按第 2 节的公式计算（最好做成可调规则，便于调数值）。 ✅ 已实现（`starter-army`，公式参数均为可调规则）。
- **兵营**：从一座兵营改为步兵营、弓兵营、骑兵营三座；兵营 1 / 5 / 10 / 15 级解锁 1–4 级兵；训练时间按 2.5.2 缩短；2–4 级的训练要预留道具额度接口（没有专门道具时不限制）。 ✅ 已实现（`starter-army`）；三座兵营的造价暂按原兵营的策划表实现，之后再调。
- **训练花销、维持开销、训练时间**：按总属性的幂次（花销 1.2 / 维持 0.8 / 时间 1.3）计算，花销再按兵种比例分摊到五种资源（2.5），基数和指数做成可调规则。 ✅ 已实现。
- **短缺后果**：现在的"逃兵"是每轮按固定比例（`troops.desertionRate`）处理所有消耗该资源的部队。改为：粮食、货币短缺 → 溃逃（低级优先）；金属（步兵）、木头（弓兵）短缺 → 降一级（高级优先，1 级兵溃逃）；每轮处理量 = 当前缺口 ÷ 剩余轮数，12 小时内到达平衡（2.5.3）。 ✅ 已实现；暂按"资源压到负数上限的那一刻立即处理第 1 轮"实现，之后每隔 1 小时一轮。
- **行军维持开销**：现在部队出征后离开驻军，行军期间不产生任何维持开销。改为出征时按往返时长一次预付，资源不足则出征失败，中途召回按比例返还；行军中的部队不参与溃逃 / 降级。 ✅ 已实现：召回时没用上的部分随部队带回，回城时入库（用户已确认）。
- **战斗公式**：目前只比较攻击与防御之和。改为按路计算（3.8）：攻方攻击 vs 守方防御定每路胜负；双方伤害 =（对方攻击 − 我方防御），截断到我方生命，按人数分摊到各等级、低级兵不够死时溢出到高级，各路按兵种 + 等级汇总后乘整场结果的伤亡系数。 ✅ 已实现（`battle` 插件）。
- **阵列、相克与城墙**：全新机制（第 3 节）。出征命令要带 5 路的兵种和部队分配；所有玩家城池（含资源要塞）新增"城墙"建筑（默认 1 级，提供每级基础防御和每 5 级 5% 的防御加成，资源要塞基础防御更高）和"设置防守阵列"命令（校验三个兵种各至少一路），默认阵列在首次读取时按城池 id 随机生成；战斗数值统一走"固定加值 + 百分比加成"的修改器；NPC 战斗时随机布阵（结果需可重现）；战斗按路计算、按赢的路数定结果，相克倍数做成可调规则。战报需要按路记录双方兵种、兵力、相克和损失。 ✅ 阵列、相克注册、城墙已实现（W6）；按路战斗与战报也已实现（W7）。城墙 1 级的造价（给没有城墙的旧城池补建时用）暂定为石 200 / 木 140 / 金属 30 / 货币 45、45 秒。 NPC 暂按"随机阵列 + 营寨（每路固定防御，GM 可调）"实现，NPC 部队不损耗。
- **掠夺与辅助兵种**：掠夺改为按库存百分比（大胜 50%、胜 35%、险胜 20%），再依次由隐藏仓库、幸存部队的载重截断；载重改为按等级线性增长乘兵种系数（现在是每个兵种固定的 `carry`，且按攻击力比例折算幸存者）。新增"隐藏仓库"建筑，把普通仓库的 `pvp.protected` 效果移过去。战斗插件要预留辅助兵种的注册和伤亡修改钩子（覆盖 3.8 的每一步）。 ✅ 掠夺、隐藏仓库、载重已实现（W8）；辅助兵种接口已实现（W10：不注册系列的兵种即辅助兵种，`battle.addCasualtyHook` 覆盖伤亡的每一步）。
- **战斗晋升**：全新机制。需要记录每场战斗双方按兵种、等级的阵亡与幸存（包括驻军），按 2.6 结算晋升。 ✅ 已实现（W9）；用剩的额度暂按"按兵种分别进位，进位后在上一级同样先同兵种、再跨兵种"实现。
- **行军**：增加 3 分钟的最短时间；步兵 / 弓兵基础速度改为 120 格 / 小时（可调；最初是约 28.4，试玩反馈太慢后调快）。 ✅ 已实现（`armies.minSeconds`、`starter-army.speed`）。
- **地图地形**：全新机制（第 4 节）。新增地形插件（按区块存储、按城区和资源给产出加成、GM 改地形）、地图生成与导入脚本，地图前端按地形着色，建外城候选格显示地形；`resources.productionFactor` 要支持按城区、按资源的加成；预留迷雾插槽和"按地形查询"的接口。 ✅ 已实现（W11：`terrain` 插件、`pnpm map:generate` / `map:import`）；暂按：道路网在平面上做三角剖分（不跨接缝连路），公平性只上调过低的区块。
- **英雄**：全新系统（第 5 节）。新增英雄插件、酒馆 / 书院 / 听曲楼三座建筑、六维属性与随机生成、职务（带兵、内政、驻守研究所）及其加成，并为秘境等插件预留职务注册、经验 / 装备和属性加成接口。 ✅ 已实现（W12：`heroes` 系统插件 + `starter-heroes` 内容插件 + 前端英雄页）；暂按：候选每 5 级 +1、刷新 8 小时起每级 −15 分钟（至少 1 小时）、招募费用货币 500 / 800 / 3000、"绝技"最高 130、时间类加成按 ×(1 − 百分比) 与其他倍率相乘；插件职务（如秘境冒险）可以用 `heroes.defineDuty` 注册，经验 / 装备接口尚未做。
