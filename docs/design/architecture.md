# 架构规划

> 这里放**尚未实现**的架构：以后要加的系统、预留好的接口怎么用、已知的限制和改进方向。已经实现的架构见 `README.md` 第 6 节；玩法以 `docs/design/gameplay.md` 为准。某一项实现后，把它移进 README，从这里删掉。

## 1. 以后的系统（已预留接口）

### 1.1 不透明科技 / 基金委

- 在首都注册"基金委"建筑（`buildings.define({ kinds: ['capital'], unique: true })`）。点开后可以筛选要资助的**项目**；项目**随机生成**，可能成功也可能失败。
- 每个项目无论成败都会积累"科技树隐藏点数"，提升以后项目的成功率。
- 成功的项目通过 `research.registerNode` 生成科技树之外的新节点（通常只对该玩家可见），再用 `research.grantLevel` 授予等级。
- 项目、点数、概率都由不透明科技插件自己的表来管。英雄可以作为"负责人"提出项目（英雄职务用 `heroes.defineDuty` 注册）。

### 1.2 英雄的冒险、经验与装备

- 冒险作为插件职务注册（`heroes.defineDuty`，声明 `inTown: false`），奖励道具用 `items.grant`。
- 经验 / 升级、装备、属性加成接口尚未做：做成英雄插件的扩展点（例如"属性修正提供者"），带兵、内政等效果统一读修正后的属性。

### 1.3 防御设施

- 在城墙上训练防御设施，提升每路的基础防御。通过 `battle.addModifier`（`stat: 'defense'`、`flat`）接入，具体规则在设计该插件时再定（gameplay.md 3.4）。

### 1.4 辅助兵种

- 接口已具备：不在 `battle` 注册系列的兵种就是辅助兵种；`battle.addCasualtyHook` 覆盖伤亡计算的每一步，载重可以用 `carry` 修改器。军医、辎重队的数值在设计插件时再定（gameplay.md 3.10）。

### 1.5 迷雾

- `terrain.addVisibility` 是迷雾插槽：迷雾插件决定某个玩家能看到哪些格子，地图视图按它过滤。没有迷雾插件时全部可见。

### 1.6 更多通知

- 邮箱（`mail.send`）目前只接了战报。建造完成、科技完成、英雄事件等需要时，由对应的连接插件监听事件后发信，不要改邮箱本身。

### 1.7 美术

- 45° 等距视角 + 像素风，见 `docs/design/ui.md` 第 5 节。

### 1.8 区服拆分

- 单个 D1 库约支撑几千人同时在线。更大规模时按"区服"拆分：一个区服一个库；插件只通过 `api.db` 访问数据库，拆分时不用改插件。

## 2. 已知限制与改进方向

- **GM 改规则后的耗尽时刻**：GM 修改规则导致产率变化时，已登记的资源耗尽事件不会重新计算，要等该城下一次执行命令。可以加定时任务兜底。
- **跨实体事件的结算时刻**：别的实体的事件（如军队回城）改动城池产率时，城池在事件**被处理时**结算，而不是事件时刻，误差最多一个清扫周期（约 1 分钟）。要精确可以让时间线支持"一个事件影响多个实体"。
- **防守战报的旧存储**：`pvp_reports` 表和 `pvp.defenses` 视图已被邮箱取代，前端不再使用。下个版本可以删除视图，之后再删表（先确认线上不再依赖）。
- **NPC 营地**：被打后没有冷却 / 重生；据点的掠夺仍是"幸存部队能带多少粮食就带多少"，没有按 3.9 的比例规则。
- **地图生成**：道路网在平面上做三角剖分（不跨地图接缝连路）；公平性只上调过低的区块。
- **没有训练地点的兵种**：`UnitDef.trainedAt` 为空的兵种只能通过 API 训练，界面上没有入口。内容插件定义可训练的兵种时要填写它。
- **运维**：登录接口没有频率限制；过期会话只在读取时失效，不主动清理；玩家不能改密码（见 README 第 9 节）。
