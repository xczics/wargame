# 架构规划

> 这里放**尚未实现**的架构：以后要加的系统、预留好的接口怎么用、已知的限制和改进方向。已经实现的架构见 `docs/development.md` 第 2 节；玩法以 `docs/design/gameplay.md` 为准。某一项实现后，把它移进 `docs/development.md`，从这里删掉。

## 1. 以后的系统（已预留接口）

### 1.2 迷雾

- `terrain.addVisibility` 是迷雾插槽：迷雾插件决定某个玩家能看到哪些格子，地图视图按它过滤。没有迷雾插件时全部可见。注意：1.4 起整张地形是一个文件，迷雾只能隐藏格子上的东西（城池、营寨），藏不住地形本身；要藏地形得改回按块、按权限下发。

### 1.3 更多通知

- 邮箱（`mail.send`）目前接了战报、被攻击（含流寇）、短缺、秘境冒险、"有望"类道具的结果和 GM 群发。建造完成、科技完成等需要时，由对应插件监听事件后发信（数据放进邮件，前端部件在扩展点 `mail.report` 拼成通用报告），不要改邮箱本身。

### 1.4 美术

- 45° 等距视角 + 像素风，见 `docs/design/ui.md` 第 5 节。

### 1.5 区服拆分

- 单个 D1 库约支撑几千人同时在线。更大规模时按"区服"拆分：一个区服一个库；插件只通过 `api.db` 访问数据库，拆分时不用改插件。

## 2. 已知限制与改进方向

### 2.0 统一的读写表插件：注册表 + 构建时烘焙（1.6.0，2026-10-25 敲定）

用户 2026-10-19："架构优化讨论（这个进2.0.0）：当前是各个插件维护自己的表。优势是各个插件互不打扰，缺点是，有些操作需要读写多个表完成。 是否提取出一个专门的读写表插件，统一维护/优化表格设计？因为插件不需要热插拔。尽量让所有高频/中频操作的读写表格都控制在1行？"

敲定的方案（用户 2026-10-25："我设想的是，外层插件见向它注册？"；"我们的系统不追求'热插拔'，所以可以'预烘焙'代码，提前根据注册表，预烘焙好真实执行的代码？"；"那就敲定这个按此做"）：

- **注册表**（已实现第一部分，见 development.md 2.2：`Plugin.tables`、`ctx.tablesOf`、`ctx.relations`、`derivedKind`，changelog 489）：各插件登记自己的表、给别人用的读法、派生值的种类，内核只认识登记进来的东西。还没做的：按玩家的热点字段（热点行合并要用）。
- **构建时烘焙**（第一块已做：引擎的数据库合成一层、SQL 的含义按文本解析一次，changelog 490；其余"代码形状"的烘焙本地测不出收益、线上收益主要来自快速通道，不再单独做）：插件集合在构建时固定（不热插拔；Workers 也不允许运行时 `eval`），生成直线代码：SQL 常量、跨插件联读拼好的整条语句（进同一个 batch，扁平视图照样可用）、钩子按顺序直接调用、变动戳的表单写死（不再在运行时记读了哪些表）、引擎的代理层合成一层。运行时可变的只有规则的值（GM 改规则），结构不变。
- **一份声明生成两条路径**（2026-10-25 不做）：线上实测快速通道省下的主要是按命令设计的预先计算（存好的派生值），生成器做不出这份设计，只能省样板代码；改为按使用频率逐条补快速通道（HANDOFF）。
- **热点行合并**（2026-10-25 用户选定"先不做，留到以后"）：注册表看得到各插件按玩家常读少变的字段，可以在物理上合进一行，插件仍按自己的表名读写。要改线上表结构、搬数据，做之前先出迁移方案和备份步骤给用户确认。
- **迁移**照旧手写，测试里核对"注册的结构 = 迁移后的实际结构"。
- 收益：同一条升级命令常规路径 17 ms、快速通道 6.5 ms、手写版 3.5–4 ms（线上，changelog 441–442），手写版就是生成代码要达到的形态，预计命令 CPU 降 30–60%；本地剖析里同步的大头是 D1 客户端（烘焙动不到），同步部分的收益上线后用 bench 复核（changelog 489）。语句数、响应大小、浏览器不受影响；读写行数只有热点行合并能降。步骤见 HANDOFF。

- **GM 改规则后的耗尽时刻**：GM 修改规则导致产率变化时，已登记的资源耗尽事件不会重新计算，要等该城下一次执行命令。可以加定时任务兜底。
- **跨实体事件的结算时刻**：别的实体的事件（如军队回城）改动城池产率时，城池在事件**被处理时**结算，而不是事件时刻，误差最多一个清扫周期（约 1 分钟）。要精确可以让时间线支持"一个事件影响多个实体"。
- **流寇**：不在地图上显示、不能半路拦截；新手保护看首都的建立时间和声望门槛（`protection.prestige`），老玩家要等下一次花费后才开始有流寇。
- **地图生成**：道路网在平面上做三角剖分（不跨地图接缝连路）；公平性只上调过低的区块。
- **没有训练地点的兵种**：`UnitDef.trainedAt` 为空的兵种只能通过 API 训练，界面上没有入口。内容插件定义可训练的兵种时要填写它。
- **前端**：通用控件的数据随视图整份下发，大列表（几百件装备、上千封邮件）没有分页或虚拟滚动；邮箱自己分页。`ui.grid` 每次移动重新请求整个窗口。
