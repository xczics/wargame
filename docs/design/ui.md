# 界面布局设计

> 由用户口述、Claude 整理，约定同 `docs/design/gameplay.md`：标 **【待确认】** 的是尚未决定的内容，括号里是目前的理解。

## 1. 整体划分

垂直方向分三段：

| 区域           | 高度         | 说明                             |
| -------------- | ------------ | -------------------------------- |
| 顶部：页面标签 | 固定窄带     | 切换页面；始终可见，不随内容滚动 |
| 中间：主体内容 | 占满剩余高度 | 见下                             |
| 底部：状态标记 | 固定窄带     | 始终可见，不随内容滚动           |

中间主体再水平分两栏：

- **左栏占 1/3，右栏占 2/3**。
- 两栏**各自独立滚动**，互不影响；整个页面本身不滚动。
- 每栏由一个个**内容块**自上而下排列组成。

## 2. 宽度与适配

- 宽度随屏幕变化。**最大宽度按 13 寸 Mac 的屏幕宽度**（1440px），超过后不再增加，内容居中，两边留白。
- 屏幕宽度**小于 744px**（iPad mini 竖屏宽度；用户说的"Mac mini 窄边"按此理解）时，改为手机式的**单栏**：先左栏的内容块，再右栏的内容块，整个中间区域一起滚动；顶部、底部窄带仍然固定。

## 3. 插件化

整个布局由前端核心统一管理（`web/core/App.vue`、`web/core/PageColumns.vue`）。**什么东西放在哪由后端声明**（后端插件 `ui` 的服务，经 `/api/meta` 的 `ui` 下发），前端插件只在 `setup(game)` 里用 `game.widget('<插件>.<名字>', 组件)` 注册组件（用户 2026-10-02 定的方向，见 `docs/design/architecture.md` 第 3 节）：

| 后端声明（`ctx.services.get('ui')`）                          | 作用                                                                                       |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `ui.page({ id, label, order, tab })`                          | 一个两栏页面（顶部标签；`tab: false` 不出现在标签里，由图标等用 `showPage` 打开）          |
| `ui.page({ id, label, order, widget })`                       | 一个**整页接管**的页面（地图、GM 后台这类需要大面积的界面）                                |
| `ui.block({ page, column: 'left' / 'right', widget, order })` | 往某个页面的某一栏放内容块；`page: '*'` 放到所有两栏页面                                   |
| `ui.band({ band: 'top' / 'bottom', widget, order })`          | 往顶部 / 底部窄带放内容                                                                    |
| `ui.entry({ kind, widget, order, types })`                    | 给某类**入口**放内容块（见下）；`types` 可以是函数，读 meta 时才算（例如"训练兵种的建筑"） |
| `ui.slot({ slot, widget, order })`                            | 放进别的组件里的具名插槽：`user-actions`（用户名右侧）、`hero-card`（每张英雄卡片）        |
| `ui.mail(kind, widget)`                                       | 某类邮件用哪个组件显示                                                                     |
| `ui.dynamic(() => ({ blocks, entries, slots }))`              | 依赖之后才定义的内容的声明（例如道具的快捷入口放在哪些建筑和页面），读 meta 时才算         |

声明可以带 `props`：`view`（控件读哪个视图，前端自动订阅）、`params`、以及控件自己的配置。**通用控件**（`web/widgets/`，由前端插件 `widgets` 注册，数据形状见 `src/shared/ui.ts`）：`ui.badge`（一行文字：加粗标签、数值、悬停说明）；`ui.cards`（按组分节的卡片网格：图标、颜色、数量、说明、状态行、命令按钮）与 `ui.filters`（标题、摘要、每组一个按钮、脚注；和同名 `filter` 的 `ui.cards` 共享所选组）；`ui.timers`（进行中的事：倒计时、进度条、状态行、按钮，到点自动刷新；放在入口里时只显示 `where` 等于该入口类型的条目）；`ui.rows`（分节的行列表：图标、标题与标记（如等级）、状态行、按钮、未解锁时变淡）。前后端共用的文字格式化在 `src/shared/format.ts`（时长、带图标的资源数）。后端插件只要提供一个返回对应形状的视图，就能用它们，不用写前端。

前端还有：`game.openEntry(entry)` / `game.entry`（在当前页面打开一个入口 / 读取当前入口），`game.showPage(id, entry?)`（切换页面），`game.slot(name)`（某个插槽里的组件），`game.widgetOf(name)`（按名字取组件）。后端声明了而前端没有的组件会被跳过（例如非 GM 的浏览器里没有 GM 后台的组件）。第三方可以写自己的前端插件注册组件，再在自己的后端插件里声明位置。

内容块自上而下按 `order` 排列，同一页面的内容块可以来自不同插件。

### 3.1 入口：建筑

内容块的入口除了"页面"，还有"入口"（目前是**建筑**）：

- 点击一个建筑，**右栏改为显示这座建筑上注册的内容块**，顶部有"返回"回到页面本身；左栏不变。每个页面各自记住打开的入口。
- **第一个内容块**是建筑本身（组件 `city.building`，由 `settlements` 声明，`order: -100`）：等级、效果、升级 / 建造进度等。
- 其他插件声明的内容块默认（`order: 0`）往下加；可以用 `types` 只挂在某几种建筑上（例如兵营的训练）。
- 服务端表单也能挂到建筑上：`placement: 'building'` 的表单会出现在建筑入口里，`prepare()` 收到的参数有 `settlement`、`district`、`slot` 和建筑类型 `type`。
- 入口是通用机制（`kind` 区分），以后可以有"英雄""军队"等其他入口。

## 4. 目前的摆放（可随时调整）

具体放什么在写代码时尝试，看怎么放最好。目前：

- 顶部窄带：页面标签；右侧邮件图标（带未读数，点开邮件页）、账号信息（用户名、官职与声望；GM 账号还有"GM"徽章，点开 GM 后台）。邮件和 GM 后台**没有**文字标签（用户 2026-10-01：两个入口重复）。
- GM 后台"玩家"页：选中玩家后有"以其身份游玩"按钮（确认后本浏览器登录为该玩家，GM 会话结束；回到 GM 界面要退出登录再用 GM 账号登录）。
- 底部窄带：当前城池的资源存量与产率。
- 所有两栏页面的左栏：城池切换、全局表单（例如"建立首都"）。
- 页面：城池、科技、英雄、秘境、**军队**（左栏：所有城池的驻军；右栏：所有行军，含来袭警报）、道具、**邮件**（左栏：邮件列表；右栏：打开的邮件）。
- 科技页：左栏是所有城池正在进行的研究（研究队列汇总），右栏是科技树（只读：等级、效果、正在研究、缺少的前置科技）。
- 建筑入口：兵营点开后是训练（这座兵营在训的一批 + 排队的训练计划，可取消；训练表单只列该兵营训练的兵种；招募令和训练加速令的快捷按钮）；研究所点开后是本城的研究（进度、速度、选科技开始研究）和驻守学者；城墙点开后是防守阵列；招募英雄的建筑点开后是候选英雄。
- 整页接管：地图、GM。
- 部队页已并入军队页（用户 2026-10-01 要求）；训练不再有单独的页面。
- **聚宝阁**（用户 2026-10-01）：左栏是元宝余额和商品类别按钮（全部 / 资源 / 加速 / 增产 / 英雄 / 城建），右栏只显示所选类别的商品。
- 英雄页左栏只列挂靠在当前城池的英雄（用户 2026-10-01）。
- **道具页**（用户 2026-10-01）：左栏是类别筛选（全部 / 资源 / 加速 / 增产 / 英雄 / 城建 / 钥匙 / 杂物，带件数）；右栏默认是道具网格（图标、名称、数量），点一件右栏切换为它的说明和使用表单，"返回"回到网格。
- **道具快捷按钮**（用户 2026-10-01）：道具在定义里写 `shortcuts`（`building:<类型>` / `page:<页面>`），`items` 插件就声明在那些建筑入口 / 页面左栏放一个按钮块（`ui.dynamic`）；有道具时展开它的使用表单（确认后使用），没有时提示来源。
- **城池页**（用户 2026-10-01）：左栏有"城区"九宫格（用到第二圈外城时 5×5），按城区的真实位置摆放：中间是内城，周围是外城（显示序号和已建 / 栏位数），空位不可点；点哪一格右栏就显示哪个城区。只有一个城区的城池（要塞）不显示。可以建外城的空格显示"＋"（每格都标地形），点击后确认（地形与加成、费用、外城 n / 上限）即建造；不能再建时提示原因。原来城池页下方的"建造外城"表单去掉了（用户 2026-10-01）。

## 5. 美术方向（未来，暂未实现）

- 现在城池页是白色卡片、地图是色块，都是占位。
- **目标**：**45° 视角（等距 / isometric）+ 像素风**，**视角固定，不支持旋转**。
  - 城池页：按城区画出栏位上的建筑（像素图，按等级可有不同外观），点击建筑打开建筑入口（沿用 3.1 的入口机制）。
  - 地图页：地形、城池、NPC、行军中的军队都按同一视角画在菱形格子上。
- 实现时的约束：
  - 图块由各插件提供（建筑、地形、兵种的图标 id 已在 meta 里），绘制由前端插件完成，内容插件不直接依赖渲染方式。
  - 浅色 / 深色主题都要可读（像素图本身不随主题变，但底色、描边、文字用设计 token）。
  - 不能旋转，所以格子到屏幕坐标的换算是固定的（x、y 各一个方向），命中检测也按菱形格子做。
