# 界面布局设计

> 由用户口述、Claude 整理，约定同 `docs/design/gameplay.md`：标 **【待确认】** 的是尚未决定的内容，括号里是目前的理解。

## 1. 整体划分

垂直方向分三段：

| 区域           | 高度         | 说明                             |
| -------------- | ------------ | -------------------------------- |
| 顶部：页面标签 | 固定窄带     | 切换页面；始终可见，不随内容滚动 |
| 中间：主体内容 | 占满剩余高度 | 见下                             |
| 底部：状态标记 | 固定窄带     | 始终可见，不随内容滚动           |

中间主体再水平分两栏：

- **左栏占 1/3，右栏占 2/3**。
- 两栏**各自独立滚动**，互不影响；整个页面本身不滚动。
- 每栏由一个个**内容块**自上而下排列组成。

## 2. 宽度与适配

- 宽度随屏幕变化。**最大宽度按 13 寸 Mac 的屏幕宽度**（1440px），超过后不再增加，内容居中，两边留白。
- 屏幕宽度**小于 744px**（iPad mini 竖屏宽度）时，改为手机式的**单栏**：先左栏的内容块，再右栏的内容块，整个中间区域一起滚动；顶部、底部窄带仍然固定。顶部窄带右侧只留用户名（过长时截断），点它打开下拉菜单，里面是 `user-actions` 插槽的内容（官职与声望、GM 入口）、修改密码和退出，让页面标签占住大部分宽度。

## 3. 插件化

整个布局由前端核心统一管理（`web/core/App.vue`、`web/core/PageColumns.vue`）。**什么东西放在哪由后端声明**（后端插件 `ui` 的服务，经 `/api/meta` 的 `ui` 下发），前端插件只在 `setup(game)` 里用 `game.widget('<插件>.<名字>', 组件)` 注册组件：

| 后端声明（`ctx.services.get('ui')`）                          | 作用                                                                                          |
| ------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `ui.page({ id, label, order, tab })`                          | 一个两栏页面（顶部标签；`tab: false` 不出现在标签里，由图标等用 `showPage` 打开）             |
| `ui.page({ id, label, order, widget })`                       | 一个**整页接管**的页面（地图、GM 后台这类需要大面积的界面）                                   |
| `ui.block({ page, column: 'left' / 'right', widget, order })` | 往某个页面的某一栏放内容块；`page: '*'` 放到所有两栏页面                                      |
| `ui.band({ band: 'top' / 'bottom', widget, order })`          | 往顶部 / 底部窄带放内容                                                                       |
| `ui.entry({ kind, widget, order, types })`                    | 给某类**入口**放内容块（见下）；`types` 可以是函数，读 meta 时才算（例如"训练兵种的建筑"）    |
| `ui.slot({ slot, widget, order })`                            | 放进别的组件里的具名插槽：`user-actions`；英雄卡片上的内容改由后端 `heroes.addCardLines` 添加 |
| `ui.mail(kind, widget)`                                       | 某类邮件用哪个组件显示                                                                        |
| `ui.dynamic(() => ({ blocks, entries, slots }))`              | 依赖之后才定义的内容的声明（例如道具的快捷入口放在哪些建筑和页面），读 meta 时才算            |

声明可以带 `props`：`view`（控件读哪个视图，前端自动订阅）、`params`、`filter`（同名的控件共享所选的组 / 格子）以及控件自己的配置。**通用控件**（`web/widgets/`，由前端插件 `widgets` 注册，数据形状见 `src/shared/ui.ts`）——后端插件只要提供一个返回对应形状的视图就能用，不用写前端：

| 控件                      | 画什么                                                                                                                                                                                                                                                                                                                        | 官方界面里的例子                                                                     |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `ui.cards`                | 按组分节的卡片：布局 `nodes` 是科技树式的卡片（标题右侧标记、斜体题注）；图标、颜色、数量、说明、状态行、按钮；布局 `tiles`（小方块）/ `compact`（小按钮就地展开）；页眉、默认组、卡片下方的服务端表单；`detail` 点开显示说明、服务端表单或一组选项按钮；`where` 限定只在某页、某类入口或某一个入口（`<类型>#<入口 id>`）显示 | 聚宝阁、道具、道具快捷按钮、城池的建筑栏位（也是建筑入口的第一块）、英雄卡、候选英雄 |
| `ui.filters`              | 标题、摘要、每组一个按钮、脚注；`layout: 'row'` 按钮横排；数据有默认组时没有\"全部\"、一次只显示一组；与同名 `filter` 的 `ui.cards` 共享所选组                                                                                                                                                                                | 聚宝阁、道具页左栏                                                                   |
| `ui.rows`                 | 分节的行列表：图标、标题与标记、状态行、按钮、未解锁变淡；分节说明（`intro`）、一排小格子（`cells`）、分组按钮（`tabs`，与同名 `filter` 共享）、下拉选前端参数（`picker`）                                                                                                                                                    | 城墙、驻军、职务、守城顺序、装备栏、秘境列表与秘境商店                               |
| `ui.timers`               | 进行中的事：倒计时、进度条、状态行、按钮，到点自动刷新；放在入口里时按 `where` 筛选                                                                                                                                                                                                                                           | 训练、研究队列、行军、来袭警报、冒险中、伤员                                         |
| `ui.badge`                | 一行字：加粗标签、数值、悬停说明                                                                                                                                                                                                                                                                                              | 用户名旁的官职与声望                                                                 |
| `ui.banner`               | 横幅：图标与一行字，玩家可关闭，`key` 变了再出现                                                                                                                                                                                                                                                                              | GM 公告（`mail.announcement`，顶部窄带）                                             |
| `ui.table`                | 小表格：表头、每行第一格是行名；格子可标红 / 变淡，带悬停说明（`hint`）；表格下方的说明行；窄栏里横向滚动                                                                                                                                                                                                                     | 城池页左栏的生产表                                                                   |
| `ui.cells`                | 一小块格子：大字、小字、底注、外观；可选中（经 `filter` 共享）或点了执行按钮                                                                                                                                                                                                                                                  | 城区九宫格（`settlements.districts`）                                                |
| `ui.grid`                 | 格子地图的一个窗口：底色、图标、边框、图例；选中格子显示信息、按钮和 `placement` 的服务端表单；旁边的列表（`sides`，可带一个下拉选项）；插槽 `grid-side:<grid>` 给前端插件放面板                                                                                                                                              | 世界地图（各插件的图层合成，`world-map.addLayer / addSide`）、示例"异世界"           |
| `ui.tree`                 | 分组分列的节点：同组前置连线、别组前置标签，完成 / 进行中 / 未解锁等状态                                                                                                                                                                                                                                                      | 科技树                                                                               |
| `ui.report` / `ui.lanes`  | 报告：标记与几行字、"标签：值"（分段着色）、逐行对比表（赢 / 输着色）、脚注；邮件由 `mail.present(kind, fn)` 在读信时整形                                                                                                                                                                                                     | 战报（每路双方的兵力组成）、冒险报告、GM 群发邮件                                    |
| `ui.sync`                 | 不显示：到点刷新或执行命令，加载时已到期的命令执行一次（声明在窄带里，每页都生效）                                                                                                                                                                                                                                            | 行军到达即提交、冒险 / 疗伤结束、训练完成与来袭时刷新                                |
| 表单字段 `ui.lanes-input` | 几路分配一个池子：每路选一组、填各项数量，提示还剩多少                                                                                                                                                                                                                                                                        | 攻打的阵列                                                                           |

按钮（`UiAction`）可以带 `parts`：跟在文字后面的几段，例如费用的每种资源，不够的标红（`src/shared/format.ts` 的 `costParts`）。危险操作（取消建造 / 训练、遣散、拆解、召回、使用道具……）带 `confirm`，执行前弹出二次确认；购买之类容易误触重复的操作带 `notice`：成功后整屏半透明遮罩显示这句话，点"好的"或遮罩才关，关之前点不到别的东西（服务端表单 `FormSpec` 同样可以带 `confirm` / `notice`，没有 `notice` 时只是短暂的"完成"提示）。文字一律是 `UiText`（`{ text: '<插件id>.<key>', vars }`，服务端用 `uiTexts` 产出，前端按键查找后填入变量，见 development.md 2.8；人名用名字键，前端按语言拼写）。

前端还有：`game.openEntry(entry)` / `game.entry`（在当前页面打开一个入口 / 读取当前入口），`game.showPage(id, entry?)`（切换页面），`game.slot(name)`（某个插槽里的组件），`game.widgetOf(name)`（按名字取组件）。后端声明了而前端没有的组件会被跳过（例如非 GM 的浏览器里没有 GM 后台的组件）。第三方可以写自己的前端插件注册组件，再在自己的后端插件里声明位置；放进 `extensions/<id>/` 就会被两端自动装上（见 `docs/plugin-guide.md` 第 8 节）。

内容块自上而下按 `order` 排列，同一页面的内容块可以来自不同插件。

### 3.1 入口：建筑

内容块的入口除了"页面"，还有"入口"（目前是**建筑**）：

- 点击一个建筑，**右栏改为显示这座建筑上注册的内容块**，顶部有"返回"回到页面本身；左栏不变。每个页面各自记住打开的入口。
- **第一个内容块**是建筑本身（`buildings` 声明的 `ui.cards`，视图 `buildings.slots`，`order: -100`；就是城池页上这座建筑的那张卡，`where` 为 `building#<入口 id>`）：等级、效果、升级 / 建造进度等。
- 其他插件声明的内容块默认（`order: 0`）往下加；可以用 `types` 只挂在某几种建筑上（例如兵营的训练）。
- 服务端表单也能挂到建筑上：`placement: 'building'` 的表单会出现在建筑入口里，`prepare()` 收到的参数有 `settlement`、`district`、`slot` 和建筑类型 `type`。
- 入口是通用机制（`kind` 区分），以后可以有"英雄""军队"等其他入口。

## 4. 目前的摆放（可随时调整）

具体放什么在写代码时尝试，看怎么放最好。目前：

- 顶部窄带：页面标签；右侧邮件图标（带未读数，点开邮件页）、账号信息。邮件和 GM 后台**没有**文字标签。
- GM 后台"玩家"页：选中玩家后有"以其身份游玩"按钮（确认后本浏览器登录为该玩家，GM 会话结束；回到 GM 界面要退出登录再用 GM 账号登录）。
- 底部窄带：当前城池的资源存量与产率。
- 所有两栏页面的左栏：城池切换、全局表单（例如"建立首都"）。
- 页面：城池、科技、英雄、秘境、**军队**（左栏：所有城池的驻军；右栏：所有行军，含来袭警报）、道具、**邮件**（左栏：邮件列表；右栏：打开的邮件）。
- 科技页：左栏是所有城池正在进行的研究（研究队列汇总），右栏是科技树（等级、效果、正在研究、缺少的前置科技；研究在研究所入口里开始）。
- 建筑入口：兵营点开后是训练（这座兵营在训的一批 + 排队的训练计划，可取消；训练表单只列该兵营训练的兵种；招募令和训练加速令的快捷按钮）；研究所点开后是本城的研究（进度、速度）、一排"门类 · 阶"的筛选按钮（如"内政 · 一阶 · 开基"，横排，默认第一组）和所选组里能研究的科技（与科技树相同样式的卡片：名称与等级、题注、解锁、效果、费用与时长、"研究 N 级"），以及驻守学者；城墙点开后是城防工事与守城器械（在建项、当前效果、下一级费用）；招募英雄的建筑点开后是候选英雄。
- 整页接管：地图（格子地图 + 旁边的"周边 NPC 城池"）、GM（玩家、规则、报表、邀请码、群发、审计）。
- 秘境页：左栏是冒险中、伤员、秘境商店；右栏是按秘境分组的按钮和所选秘境的任务（选空闲英雄、预计战果、出发），左栏的秘境商店只显示所选秘境的装备；选中未开启的秘境时也列出它的装备和价格，但购买按钮禁用（"开启这个秘境后才能购买"）。
- 英雄页：左栏页眉是"本城 n 名 · 英雄 x / 上限"（到上限标红），下面是本城英雄的卡片（"管理"里是职务、改挂靠、分配点数、遣散；分配点数是六行的表：属性、合计、初始、天赋、加成、已加点、本次加点），右栏是候选英雄、装备栏与守城顺序。
- 顶部窄带下方：GM 的公告横幅（玩家可关闭）。
- 部队在军队页；训练在各兵营的入口里，没有单独的页面。
- **聚宝阁**：左栏是元宝余额和商品类别按钮（全部 / 资源 / 加速 / 增产 / 英雄 / 城建），右栏只显示所选类别的商品。
- 英雄页左栏只列挂靠在当前城池的英雄。
- **道具页**：左栏是类别筛选（全部 / 资源 / 加速 / 增产 / 英雄 / 城建 / 钥匙 / 杂物，带件数）；右栏默认是道具网格（图标、名称、数量），点一件右栏切换为它的说明和使用表单，"返回"回到网格。
- **道具快捷按钮**：道具在定义里写 `shortcuts`（`building:<类型>` / `page:<页面>`），`items` 插件就声明在那些建筑入口 / 页面左栏放一个按钮块（`ui.dynamic`）；有道具时展开它的使用表单（确认后使用），没有时提示来源。
- **城池页**：左栏有"城区"九宫格（用到第二圈外城时 5×5），按城区的真实位置摆放：中间是内城，周围是外城（显示序号和已建 / 栏位数），空位不可点；点哪一格右栏就显示哪个城区。只有一个城区的城池（要塞）不显示。可以建外城的空格显示"＋"（每格都标地形），点击后确认（地形与加成、费用、外城 n / 上限）即建造；不能再建时提示原因。

## 5. 美术方向（未来，暂未实现）

- 现在城池页是白色卡片、地图是色块，都是占位。
- **目标**：**45° 视角（等距 / isometric）+ 像素风**，**视角固定，不支持旋转**。
  - 城池页：按城区画出栏位上的建筑（像素图，按等级可有不同外观），点击建筑打开建筑入口（沿用 3.1 的入口机制）。
  - 地图页：地形、城池、NPC、行军中的军队都按同一视角画在菱形格子上。
- 实现时的约束：
  - 图块由各插件提供（建筑、地形、兵种的图标 id 已在 meta 里），绘制由前端插件完成，内容插件不直接依赖渲染方式。
  - 浅色 / 深色主题都要可读（像素图本身不随主题变，但底色、描边、文字用设计 token）。
  - 不能旋转，所以格子到屏幕坐标的换算是固定的（x、y 各一个方向），命中检测也按菱形格子做。
