  - **装备（equipment / starter-equipment）**：服务端新造的每件装备（秘境商店、宝箱、奖励、掉落、商人）回 `equipment.created`：整件（id、存放的城、底子、颜色、属性：浏览器什么都没有），装备前端加进那座城的 `equipment.items`。招募来的英雄在装备行里的饰品数由浏览器算：共享 `accessoriesOf`（`src/shared/starter-equipment.ts`），上限进静态 `starter-equipment.accessories`，装备前端服务新方法 `setGroupLimit`。`HeroInfo` 补上本来就发着的 `extras`。
  - **英雄（heroes / rebirth）**：别的插件给的英雄（拼图、邮件、道具）的 `heroes.created` 只在给的是本人时回。转生成功回 `rebirth.reborn`：`{ hero, talents, freePoints }`（随机加的天赋），浏览器用和服务端同一份的 `reincarnated`（`src/shared/heroes.ts`，服务端 `heroes.reincarnate` 也用它）改英雄、星数加一；失败什么都不改（以前记为旧）。**进静态**：转生的等级和次数上限进静态 `rebirth.rules`，转生丹表单只发各英雄已转几次。
  - **奖励（starter-rewards）**：英雄、装备奖励不再记为旧（回包带着）。
  - **声望（prestige）**：**进静态**：头衔表进静态 `prestige.ranks`，视图 `prestige.status` 只发声望值和最高值（`PrestigeData`），浏览器用共享 `prestigeOf` / `rankAt` 算头衔（服务端也用 `rankAt`）。
  - **兵种费用进静态**：训练表单（`TrainFormData.units`）和驻军的可训练列表（`GarrisonInfo.trainable`）不再带每种兵的费用，浏览器取静态 `troops.units`（测试的表单输入改为带上全部静态视图）。
  - **道具（starter-items）**：去掉多余的 `forms.patches` 记旧（任何命令之后核心已经记旧了），计时改用命令时钟。商路买到的装备、宝箱开出的装备由 `equipment.created` 补进，不再记为旧。
  - **仍记为旧的（原因）**：商路交战（胜负、伤亡、掉落、经验、顿悟都是服务端的一场战斗，回包太大，只在商路页发，那页的回答已带商路视图）；商路出发后的商人（开拓队落脚处的货由服务端定）；概率道具（扩展许可、地契、突破石、特许、属性类）成功后的结果和听曲楼请帖 / 酒馆、书院换人（候选人整份随机，等于整份视图）；丰收祭、夷平令后的产量明细（全部来源的合计）；工部令 / 兵部令 / 翰林令提前到现在完工的那一项（完工后的等级、产量、下一批开工都是服务端的）；奖励池（抽中哪一项只在服务端，且掉落时也会抽，回话对不上号）、城防奖励；GM 发拼图碎片；建外城后的地图窗口（各图层的数据）；加入大对象时缺静态数据或缺持有的英雄时退回记为旧。
  - **小助手只按玩家按得动的按钮**（用户："小助手只是'秘书'，玩家做不了的事情，小助手也做不了！"）：每条命令发出前都过界面同一份判断：科研 `researchBlocked`（科技页按钮的原因，从 `web/plugins/research/tree.ts` 挪进 `src/shared/research.ts`，填平原则挑科技时也用它）；秘境出发 `adventureBlocked`（秘境页"出发"按钮，挪进 `src/shared/realms.ts`，读当时的 `realms.info`）；穿装备 `tooLow`（纸娃娃的"穿上"，挪进 `src/shared/equipment.ts`）并且英雄要能换装；加点 `pointsFit`；派职 / 卸任 `heroFree`（英雄卡片表单的显示条件，挪进 `src/shared/heroes.ts`）；打营寨 `unitsFit`（派兵表单每格的"最多"，挪进 `src/shared/troops.ts`）。服务端不变。
