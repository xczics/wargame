# 2026-10-19 用户留言与改动

- ✅ 292 **1.4.1 性能：定时任务、地图窗口、地图表单、空的状态请求**（用户 2026-10-19："再优化一轮性能"；测试数据 `running_log/testdata.zip`）。
  - 依据：1.4.0 的用量日志里，00:00–04:00 没人玩，240 次定时任务读了 11.4 万行（每次约 475 行，占免费额度约 14%）；有人玩时 4 小时 28 万行。用户的存档是 1.4 之前开的世界（存着 1.3 万座营寨）。
  - 逐页测量：开着 `USAGE_LOG` 时，每个响应带 `x-usage-rows: 读,写`（新的开发用响应头，线上不开就没有），在用户存档的副本上逐页、逐视图、逐条查询看读行数。
  - `settlements.topUpSlots`（补齐栏位）：原来每小时、每次 isolate 启动都把所有城区和城池联表全扫（约 2.7 万行，平摊每分钟约 450 行，就是空闲时的大头）。现在只在固定栏位数变了（GM 改规则）时才扫，从玩家城池按 `owner_id` 索引出发（7 行），补完的大小存在新表 `settlements_task_state`（迁移 `0018`），isolate 重启后只读这一行。测试：`api.spec` 新增"只在大小变化时扫描"。
  - `worldMap.window`：`x BETWEEN … AND y BETWEEN …` 在 (x, y) 主键上只能用到 x 的范围，会把这几列从上到下所有存着的格子读一遍。改为 `x IN (逐列) AND y BETWEEN`（列数不超过 90 时，绑定参数上限 100），每列直接定位到 y 的范围。用户存档里 15×15 的窗口从 602 + 220 行降到几十行；地图页一次同步 1,017 → 351 行。
  - 地图格子的表单（用户 2026-10-19："地图页 军队派遣/建城/攻打 表单，不是点击才展开，真的不会增加额外读表负担吗？"）：确实会。选中格子后表单作为 `ui.forms` 实例跟着每次同步重算（约 40 行），而且每点一个格子，前端都把整页重新同步一遍（连地图网格，约 384 行）。改为：
    - 格子选中后先显示信息和"操作"按钮，点了才加载表单，展开后换格子保持展开；
    - `game.instance` 新注册的实例只单独请求它们自己，不再带上整页的视图和网格（其他页面的表单同样受益）。
  - 状态接口不带 `views` 时原来计算全部视图（用户存档上一次 2,203 行），客户端从不这样请求，等于留了一个贵的口子；改为不计算任何视图。
  - 其余各页每次同步约 100 行，读的都是玩家自己的数据（建筑、科技、英雄、驻军……现算产率要用），属于 2.0.0 待讨论的"一实体一行"方向，这一轮不动。
  - 顺手：vitest 和 `.gitignore` 排除 `.claude/worktrees/`（并行工作区里的测试副本不该被收进来）。
- ✅ 293 **1.4.1 数值：钱庄、军队维持费、资源要塞、伤害公式**（用户 2026-10-19 的测试评论）。
  - 钱庄（"钱庄产量曲线略微调陡峭一点，前十级比线性曲线陡峭一点点，同时第十级产量是现在的三倍。后面的倍率设计保持不变。"）：建筑新增 `producesPower`（到第一个增长阶段前按 等级^指数，默认 1 即线性；`stagedGrowth` 加可选参数，前后端共用）。钱庄 0.0568 × 等级^1.2：1 级 0.057（原 0.03）、10 级 0.9（原 0.3），11 级起仍 ×1.12、21 级起 ×1.15。建筑的产量和曲线也成了 GM 规则 `buildings.rules` 的字段（`produces`、`producesPower`，部分覆盖），这样升级结算能按旧值算（见 294）。
  - 军队维持费（"维持开销，金币提高到原来的三倍，相应地降低粮草开销。"）：各兵种货币 15% → 45%，粮食减 30 个百分点（步兵、弓兵 75 → 45，骑兵 85 → 55），总量不变。
  - 资源要塞（"相同城防器械提供的防御数值比其他城池乘3，城防设施维护消耗减半，且不再消耗金币……"）：新规则 `starter-siege.kinds`（按城池类型：`strength` 器械防御倍数、`upkeep` 城防维持费倍数、`noGold` 货币部分按比例分摊给其他资源）；资源要塞默认 3 / 0.5 / 1。防御倍数作为"器械强度"stat 的固定部分（科技百分比仍在其上），加成明细里显示为"资源要塞"；维持费在 `upkeepOf` 里统一处理，结算、城防卡片、城防表格三处一致。
  - 伤害（"之前规则容易导致只要有兵力优势，士兵就很难阵亡。"，用户选定比例式）：一路受到的伤害 = 对方攻击² ÷（对方攻击 + 我方防御）× 伤害系数（新规则 `battle.damageFactor`，默认 1），再按原来的算法分摊、截断、乘结果系数。设计示例（100 骑对 100 骑）攻 / 守伤亡比率 15% / 5% → 61.5% / 58.8%；玩法 3.8 节已改。
  - 测试：钱庄曲线（10 级 0.9、前十级在线性与 1.5 次方之间、11 级 ×1.12、农田仍线性）；维持费比例；资源要塞（维持费只剩石头且减半、器械强度 3）；战斗用例按新公式改写（设计示例用公式算期望值）。

- ✅ 296 **1.4.1 bug 与显示**（用户 2026-10-19 的测试评论）。
  - 手机端"新建拼图没反应"：新建时调用 `crypto.randomUUID()`，浏览器只在 https / localhost 提供它，手机经局域网地址用 http 访问时不存在，一点就抛错。用 Playwright 以局域网 IP 访问实测确认（`isSecureContext: false`、`randomUUID: undefined`）。改用新的共享函数 `randomId()`（`src/shared/random.ts`，基于 `crypto.getRandomValues`，非安全上下文也能用）；前端没有别处用它。
  - "没找到隐藏维度对应关系的入口"：GM 后台新增"不透明科技"页签（`opaque-research.gm`）：圆环分组编辑器（和规则页同一个控件、同一条规则，可保存 / 撤销 / 恢复默认），以及每段包含第几到第几维、各维的代号（如"乾·初"）和这一段给的加成。数据都来自已下发的静态文本，不加接口。
  - 战报 i18n（"结果：grade:crushing""带兵英雄 attack +24.3%"）和行军列（"victory · npc-camps.Militia Checkpoint"）：几处把键当普通字符串传进了 UiText 的变量（前端对字符串变量原样显示）。改为 `text(...)`；结果词在 `armies` 的翻译表里补上；"目标名，没有就用城池类型名"原来在战报插件里写了一份，行军列是第二处要用，挪成 `settlements.labelOf`，两边共用；手拼的百分号改用共享的 `signed`。测试断言邮件战报和行军列里不再有键当字符串的情况。
  - 城防工事偶发"资源不足"：下单按"已建成 + 已排队"之后的那一级收费，卡片上的"下一级"却只看已建成的等级，而且读的是内容表的原始费用（不是 GM 规则里的）。有一级在排队时，再点一次实际收的是更贵的下一级。改为卡片和城防视图都按排队后的下一级、规则里的费用、效果和用时显示，有排队时注明"已排队到 n 级"。测试：排一级后卡片的费用正好等于下一单实际扣的钱。
  - 秘境"每组掉落价值 0"：1.3.3 把掉落价值乘了 0.04（现在 0.006–0.066），按一位小数显示都成了 0。新增共享格式化 `significant`（小于 1 的数保留两位有效数字），秘境改用它。
  - 建城表单没有出发城池的上限（"举一反三复查。是不是该复用的没复用，各写一套了？"）：确实是各写一套。资源格子的"最多 X"只在运输表单自己的 `prepare` 里算，其他出兵表单都没有。改为在共用的 `armies.sendForm` 里给兵种格子（按所选出发城池的驻军，`placeholderBy`）和资源格子（实时库存，`placeholderLive`）统一加上，建城、派遣、攻打、运输都有了；运输表单只保留它特有的"取回"部分。复查其他数量框：遣散部队加"最多 N"、城防器械加"最多能造几个"（按库存和单批上限）；一键集合的标签里已有数量和上限。
  - 不透明科技面板（"只显示总效果，不显示分组（和GM的设置解偶）。只显示已获得的效果"）：同一加成项不论分在几组都合计成一行，没获得的不显示；一项都没有时提示去双清观。
  - 装备筛选（"筛选功能不止用于拆解，也用于减小列表长度"）：通用行列表控件新增 `RowsData.facets` / `UiRow.facets`（浏览器里按下拉框过滤，不发请求）；装备的存放列表带颜色 / 套装 / 部位三个筛选，选项只列有的值，和批量熔炼共用 `facetChoices`。顺手修了熔炼表单里没有名字的套装把 id 当键用的隐患。
  - 道具快捷位置（"研究加速道具按钮没有出现在研究所里。举一反三，应放尽放。"）：研究加速放进研究所和科技页，建造加速、资源券、丰收祭、突破石、扩建许可、地契、改名、迁建、交换放进城池页，练兵加速加上军队页，治伤药放进秘境和英雄页，经验书、洗点丹、名帖放进英雄页，建城文书放进地图页（`items.csv` 的 `shortcuts`，由 `ui.dynamic` 自动挂上）。
